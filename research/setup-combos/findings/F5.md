## 1. Microsoft GraphRAG

### What Is It
A **Python library** (not a Docker service) from Microsoft Research that extracts a knowledge graph from unstructured text using LLMs, builds community hierarchies via Leiden clustering, and generates summaries for retrieval. It is a **data pipeline**, not a runtime service.

### How It Works
1. **Index**: Slice corpus into TextUnits → Extract entities/relationships → Leiden hierarchical clustering → Community summaries
2. **Query**: Global search (community-level holistic questions), Local search (entity-specific fan-out), DRIFT search (entity + community context)
3. **Prompt Tuning**: Auto-tune or manually tune prompts for your domain

### Key Details
| Attribute | Value |
|-----------|-------|
| **GitHub** | `microsoft/graphrag` |
| **Stars** | 34.4k |
| **License** | MIT |
| **Language** | Python |
| **Docker** | No official Docker image (CLI tool) |
| **Latest Version** | v3.1.0 (May 2026) |
| **Requires** | LLM API key (OpenAI GPT-4 by default) |
| **Storage** | Parquet files (entities, communities, relationships, text units) |

### Neo4j/Qdrant Integration
- **No native Neo4j or Qdrant integration.** GraphRAG stores data in Parquet files.
- You can export the graph and load it into Neo4j manually.
- Vector search is not native — it uses community summaries + graph traversal.
- Some community adapters exist to export to Neo4j for visualization.

### Relevance to Setup MNO
- GraphRAG is a **batch indexing tool**, not a runtime service. It cannot be deployed as a Docker container alongside the existing stack.
- However, the **GraphRAG methodology** (entity extraction → community detection → hierarchical summaries) can be replicated using Cognee or Graphiti, which ARE Docker-deployable services.
- **Verdict**: Use as reference architecture, not as a direct component.

## 2. Cognee

### What Is It
The **open-source AI memory platform for agents**. Cognee builds a self-hosted knowledge graph that gives agents persistent long-term memory across sessions. It combines vector embeddings, graph reasoning, and cognitive-science-grounded ontology generation.

### Key Details
| Attribute | Value |
|-----------|-------|
| **GitHub** | `topoteretes/cognee` |
| **Stars** | 27.9k |
| **License** | Apache-2.0 |
| **Language** | Python |
| **Docker Image** | `cognee/cognee:main` (API), `cognee/cognee-mcp:main` (MCP server) |
| **Latest Version** | v1.3.0 (Jul 2026) |
| **Requires** | LLM API key (OpenAI default) |

### Docker Deployment
```yaml
# API Server
docker run --env-file ./.env -p 8000:8000 --rm -it cognee/cognee:main

# MCP Server
docker run -e TRANSPORT_MODE=http --env-file ./.env -p 8000:8000 --rm -it cognee/cognee-mcp:main

# Docker Compose with optional profiles
docker compose --profile postgres up   # + Postgres/PGVector
docker compose --profile neo4j up      # + Neo4j
docker compose --profile ui up         # + Frontend
docker compose --profile mcp up        # + MCP server
```

### Features
- **remember/recall/forget/improve** API — 4 operations for memory lifecycle
- **Session memory** with background sync to permanent graph
- **Auto-routing** — picks best search strategy (vector, graph, hybrid) automatically
- **MCP server** — integrates with Claude Code, OpenClaw, and other MCP clients
- **OpenClaw plugin** — `@cognee/cognee-openclaw` npm package
- **Claude Code plugin** — persistent memory across coding sessions
- **BEAM benchmark**: 0.79 at 100K tokens, 0.67 at 10M tokens (beats previous SOTA)

### Database Support
| Backend | Type | Status |
|---------|------|--------|
| **PostgreSQL + pgvector** | All-in-one (recommended) | Default, runs ~10% faster than separate backends |
| **Neo4j** | Graph | Full support via docker-compose profile |
| **Qdrant** | Vector | Community adapter |
| **ChromaDB** | Vector | Community adapter |
| **Weaviate** | Vector | Community adapter |
| **Milvus** | Vector | Community adapter |
| **LanceDB** | Vector | Local/embedded mode |
| **KuzuDB** | Graph | Local/embedded mode |
| **SQLite** | Local | Local/embedded mode |

### Postgres-Only Mode (cognee 1.0+)
Cognee 1.0 introduced running the **entire memory layer on a single Postgres instance**:
- Graph: `GRAPH_DATABASE_PROVIDER=postgres`
- Vectors: `VECTOR_DB_PROVIDER=pgvector`
- Sessions: `CACHE_BACKEND=postgres`
- Metadata: same Postgres

This eliminates Neo4j + Qdrant + Redis for most deployments.

### Relevance to Setup MNO
**STRONG candidate** — already in the OPENCLAW + QDRANT + NEO4J + COGNEE stack. Cognee is the "brain" that orchestrates knowledge across Neo4j (graph) and Qdrant (vectors). The Postgres-only mode could simplify the stack by replacing Neo4j + Qdrant with a single Postgres instance.

## 3. RAGFlow (infiniflow/ragflow)

### What Is It
A **leading open-source RAG engine** that fuses cutting-edge RAG with Agent capabilities. Focuses on deep document understanding with template-based chunking and grounded citations.

### Key Details
| Attribute | Value |
|-----------|-------|
| **GitHub** | `infiniflow/ragflow` |
| **Stars** | 85.1k |
| **License** | Apache-2.0 |
| **Language** | Go + Python + TypeScript |
| **Docker Image** | `infiniflow/ragflow:v0.26.4` |
| **Latest Version** | v0.26.4 (Jul 2026) |
| **Requires** | Docker Compose, MySQL, Elasticsearch/Infinity, MinIO, Redis |

### Docker Deployment
```bash
git clone https://github.com/infiniflow/ragflow.git
cd ragflow/docker
docker compose -f docker-compose.yml up -d
# Access at http://localhost
```

### System Requirements
- CPU >= 4 cores, RAM >= 16 GB, Disk >= 50 GB
- Docker >= 24.0.0 & Docker Compose >= v2.26.1
- vm.max_map_count >= 262144

### Features
- **Deep document understanding** — parses complex formats (PDF, DOCX, images, scanned copies)
- **Template-based chunking** — intelligent, explainable, multiple templates
- **Grounded citations** — traceable references to source text chunks
- **Agent workflows** — agentic workflow + MCP support
- **Multi-model support** — OpenAI, Claude, Gemini, DeepSeek, Ollama
- **Multiple chat channels** — Feishu, Discord, Telegram, Line
- **Data sync** — Confluence, S3, Notion, Discord, Google Drive

### Storage Architecture
- **Elasticsearch** (default) or **Infinity** for full text + vectors
- **MySQL** for metadata
- **MinIO** for file storage
- **Redis** for caching

### Neo4j/Qdrant Integration
- **No native Neo4j or Qdrant support.** Uses Elasticsearch or Infinity for both full-text and vector search.
- RAGFlow is a **complete platform** with its own document parsing, chunking, and retrieval — it doesn't rely on external vector/graph databases.

### Relevance to Setup MNO
**Excellent for document-heavy use cases.** RAGFlow is the best-in-class RAG engine for document ingestion with deep understanding. However, it's a **full stack** (MySQL + ES + MinIO + Redis) — heavy for a combo. Best added as a standalone tool rather than integrated into the core GraphRAG pipeline. Could replace or complement SearXNG for document search.

## 5. Mem0 (mem0ai/mem0)

### What Is It
The **universal memory layer for AI agents** — a dedicated memory infrastructure that remembers user preferences, adapts to individual needs, and continuously learns over time.

### Key Details
| Attribute | Value |
|-----------|-------|
| **GitHub** | `mem0ai/mem0` |
| **Stars** | 60.9k |
| **License** | Apache-2.0 |
| **Language** | Python + TypeScript |
| **Docker** | `docker compose up` in `server/` directory |
| **Latest Version** | v3.x (2026) |
| **Requires** | LLM API key, Qdrant (default vector store) |

### Deployment Options
1. **Library** (pip install) — testing/prototyping
2. **Self-hosted Server** (Docker) — teams on own infrastructure
3. **Cloud Platform** (app.mem0.ai) — zero-ops production

### Self-Hosted Docker
```bash
cd server && make bootstrap  # Start stack + create admin + issue API key
# OR
cd server && docker compose up -d  # Then http://localhost:3000
```

### Features
- **Multi-Level Memory**: User, Session, and Agent state
- **New Memory Algorithm (April 2026)**:
  - Single-pass ADD-only extraction (no UPDATE/DELETE)
  - Entity linking across memories
  - Multi-signal retrieval (semantic + BM25 + entity matching)
  - Temporal reasoning (time-aware retrieval)
- **Benchmark**: 92.5 on LoCoMo (+21 points), 94.4 on LongMemEval (+27 points)
- **CLI**: `mem0 add`, `mem0 search` from terminal
- **Agent Skills**: MCP-compatible for Claude Code, Codex, Cursor, Windsurf
- **OpenMemory**: open-source memory management UI

### Storage
- **Qdrant** — default vector store
- **Neo4j** — optional graph backend
- **PostgreSQL** — metadata/session storage
- Supports: Qdrant, Neo4j, ChromaDB, Pinecone, Weaviate, Milvus, pgvector

### Neo4j/Qdrant Integration
**Native support for both.** Mem0's default stack is Qdrant (vectors) + PostgreSQL (metadata). Neo4j is supported as an optional graph backend for relationship tracking.

### Benchmark Results (April 2026)
| Benchmark | Score | Tokens | Latency p50 |
|-----------|-------|--------|-------------|
| LoCoMo | 92.5 | 7.0K | 0.88s |
| LongMemEval | 94.4 | 6.8K | 1.09s |
| BEAM (1M) | 64.1 | 6.7K | 1.00s |
| BEAM (10M) | 48.6 | 6.9K | 1.05s |

### Relevance to Setup MNO
**STRONG candidate** — Mem0 is the most popular memory layer (60.9k stars). It integrates natively with Qdrant and Neo4j, which are already in the Setup MNO stack. The self-hosted server with Docker is production-ready. **Mem0 could complement or replace parts of Cognee's memory functionality**, or they could work together (Cognee for knowledge graph + Mem0 for agent memory).

## 6. Zep + Graphiti

### What Is It
- **Zep Cloud**: Managed agent memory platform (closed-source service)
- **Graphiti**: Open-source temporal context graph engine — the core of Zep's context infrastructure

### Zep (getzep/zep)
| Attribute | Value |
|-----------|-------|
| **GitHub** | `getzep/zep` |
| **Stars** | 4.8k (examples repo) |
| **License** | Apache-2.0 |
| **Status** | **Zep Community Edition is DEPRECATED** — now cloud-only service |
| **SDK** | `pip install zep-cloud`, `npm install @getzep/zep-cloud` |

**Key Point**: Zep itself is no longer self-hostable as open source. The open-source component is **Graphiti**.

### Graphiti (getzep/graphiti)
| Attribute | Value |
|-----------|-------|
| **GitHub** | `getzep/graphiti` |
| **Stars** | 28.8k |
| **License** | Apache-2.0 |
| **Language** | Python |
| **Docker** | Yes (`docker compose up` starts Neo4j + Graphiti MCP server) |
| **Latest Version** | v0.29.2 (Jun 2026) |
| **Requires** | Neo4j 5.26+ or FalkorDB 1.1.2+ or Amazon Neptune |

### What Graphiti Does
Builds **temporal context graphs** — knowledge graphs that track how facts change over time:

- **Entities** with evolving summaries
- **Facts/Relationships** with temporal validity windows (bi-temporal tracking)
- **Episodes** — raw data provenance (every fact traces back to source)
- **Custom ontology** via Pydantic models
- **Incremental updates** — no batch recomputation
- **Hybrid retrieval** — semantic + BM25 + graph traversal

### Graphiti vs GraphRAG (Microsoft)
| Aspect | GraphRAG | Graphiti |
|--------|----------|----------|
| Primary Use | Static document summarization | Dynamic, evolving context for agents |
| Data Handling | Batch-oriented | Continuous, incremental |
| Temporal Handling | Basic timestamps | Explicit bi-temporal with fact invalidation |
| Query Latency | Seconds to tens of seconds | Sub-second |
| Custom Entity Types | No | Yes (Pydantic models) |

### Docker Compose (Graphiti)
```yaml
# Starts Neo4j + Graphiti MCP server
docker compose up
# For FalkorDB instead of Neo4j:
docker compose --profile falkordb up
```

### Neo4j/Qdrant Integration
- **Neo4j**: Primary graph backend (required, or use FalkorDB/Neptune as alternatives)
- **Qdrant**: Not directly used by Graphiti (uses Neo4j's built-in vector index or external embedder)
- Graphiti supports: Neo4j, FalkorDB, Amazon Neptune

### Relevance to Setup MNO
**CRITICAL for the Setup MNO stack.** Graphiti (via Zep) is the **temporal knowledge graph engine** that makes the OPENCLAW + QDRANT + NEO4J + COGNEE + SEARXNG stack work as "AI with infinite memory." Graphiti handles:
- Real-time knowledge graph construction
- Temporal fact tracking (what's true now vs. what was true before)
- Provenance (every fact traces back to source data)
- Hybrid retrieval (semantic + keyword + graph)

**Key insight**: Zep Cloud is the managed version; Graphiti is the self-hosted OSS engine. For Setup MNO, use Graphiti with Neo4j.

```
    ↕
Neo4j (knowledge graph) + Qdrant (vectors)
    ↕
SearXNG (web search)
```

### Relevance to Setup MNO
Open WebUI is the **frontend layer** for the Setup MNO stack. It connects to Ollama for inference and can use Qdrant as a vector store. Combined with Cognee for memory orchestration and Graphiti for temporal knowledge graphs, this forms the complete "AI with infinite memory" stack.

### Simplified Stack (Postgres-Only)

```
Ollama + Open WebUI + Cognee (Postgres-only) + SearXNG + N8N
```
This eliminates Neo4j and Qdrant, replacing them with PostgreSQL + pgvector.

## Key Findings

### 1. Cognee is the Central Orchestrator
Cognee is the best OSS memory platform — it supports Neo4j, Qdrant, PostgreSQL, has MCP server, OpenClaw plugin, Claude Code plugin, and the Postgres-only mode simplifies deployment.

### 2. Graphiti is the Temporal Layer
Graphiti (from Zep) adds bi-temporal knowledge graph capabilities that no other tool provides. It's essential for "AI that remembers how things change over time."

### 3. Mem0 is the Agent Memory Layer
Mem0 excels at user-level and session-level memory. It's the most popular memory layer (60.9k stars) with best benchmark scores. It complements Cognee/Graphiti.

### 4. RAGFlow is Best for Document Ingestion
85.1k stars — the most popular RAG engine. Its deep document understanding (PDF, DOCX, images) is unmatched. Heavy stack (MySQL + ES + MinIO + Redis) but worth it for document-heavy use cases.

### 5. PostgreSQL-Only Mode is a Game Changer
Cognee 1.0+ can run the entire memory layer on PostgreSQL. This could simplify the Setup MNO stack significantly — one database instead of three (Neo4j + Qdrant + Postgres).

### 6. Open WebUI + Ollama is the Frontend Standard
146k stars — the dominant self-hosted AI UI. Supports 9 vector databases, SearXNG integration, MCP, persistent memory. Perfect frontend for the knowledge management stack.

### 7. Zep Community Edition is Dead
Zep pivoted to cloud-only. The open-source component is Graphiti. For self-hosted, use Graphiti directly with Neo4j.
