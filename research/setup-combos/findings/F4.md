## 1. Loki + Grafana (Log Aggregation)

### Docker Image
- **Loki**: `grafana/loki:3.7.0` (porta 3100)
- **Alloy**: `grafana/alloy:latest` (coletores — substitui o Promtail)
- **Promtail**: `grafana/promtail:latest` (deprecated em favor do Alloy)

### Como Funciona
Loki é o "Elasticsearch dos pobres" — indexa labels (não conteúdo de texto), consumindo ~10x menos memória. O **Grafana** já existe no MNO, então Loki é uma adição perfeita: basta adicionar como data source.

### Docker Swarm Stack YAML
```yaml
version: "3.7"
services:
  loki:
    image: grafana/loki:3.7.0
    command: -config.file=/etc/loki/loki-config.yaml
    volumes:
      - loki-data:/loki
    networks:
      - interna
    deploy:
      resources:
        limits:
          memory: 512M

  alloy:
    image: grafana/alloy:latest
    volumes:
      - /var/log:/var/log:ro
      - /var/run/docker.sock:/var/run/docker.sock:ro
    networks:
      - interna
    command: run --storage.path=/tmp/alloy /etc/alloy/config.alloy
    deploy:
      mode: global

volumes:
  loki-data:
networks:
  interna:
    external: true
```

### Integração com MNO
- **Grafana existente**: Adicionar Loki como data source via Settings > Data Sources > Loki > `http://loki:3100`
- **Prometheus existente**: Loki é complementar (métricas vs logs)
- **Dozzle**: Loki substitui parcialmente o Dozzle (histórico de logs vs real-time)
- **Traefik**: Alloy coleta logs do Traefik automaticamente via Docker socket
- **Portainer**: Deploy via stack YAML upload

### Recomendação para MNO
**ALTA PRIORIDADE**. Pode ser ofrecido como combo "Grafana + Loki" — extensão natural do monitoramento existente. O Alloy roda como daemon (global mode) em cada nó do Swarm, coletando logs de todos os containers.

## 2. Tempo (Distributed Tracing)

### Docker Image
- **Tempo**: `grafana/tempo:latest` (monolithic mode, porta 3200)
- **Tempo Query Frontend**: `grafana/tempo-query-frontend:latest`

### Como Funciona
Grafana Tempo é um sistema de tracing distribuído de baixo custo. Armazena traces em object storage (local filesystem ou S3). Recebe traces via OTLP, Jaeger, Zipkin.

### Docker Swarm Stack YAML
```yaml
version: "3.7"
services:
  tempo:
    image: grafana/tempo:latest
    command: -config.file=/etc/tempo/tempo.yaml
    volumes:
      - tempo-data:/var/tempo
      - tempo-config:/etc/tempo
    networks:
      - interna
    deploy:
      resources:
        limits:
          memory: 512M

  tempo-query:
    image: grafana/tempo-query:latest
    command: --grpc-plugin-server-endpoint=tempo:4317
    networks:
      - interna

volumes:
  tempo-data:
  tempo-config:
networks:
  interna:
    external: true
```

### Integração com MNO
- **Grafana existente**: Adicionar Tempo como data source > Tempo > `http://tempo:3200`
- **n8n, Chatwoot**: Podem instrumentar para enviar traces via OTLP
- **PostgreSQL**: O driver `pgx` do Go suporta trace injection
- **Uso com Loki**: Correlacionar logs (Loki) com traces (Tempo) via traceID

### Recomendação para MNO
**MÉDIA PRIORIDADE**. tracing distribuído é avançado para o público MNO (criadores de cursos). Pode ser ofrecido como combo "Grafana + Loki + Tempo" para usuários avançados.

## 4. Gotify (Push Notifications)

### Docker Image
- **Gotify Server**: `gotify/server` (porta 80)
- Suporta: amd64, i386, arm64, armv7, riscv64

### Como Funciona
Gotify é um servidor de mensagens push self-hosted com app Android. Cada cliente registra um token e recebe push notifications via WebSocket.

### Docker Swarm Stack YAML
```yaml
version: "3.7"
services:
  gotify:
    image: gotify/server
    volumes:
      - gotify-data:/app/data
    environment:
      - GOTIFY_DEFAULTUSER_PASS=admin
      - TZ=UTC
    networks:
      - externa
    deploy:
      mode: replicated
      replicas: 1
      placement:
        constraints:
          - node.role == manager
      labels:
        - traefik.enable=true
        - traefik.http.routers.gotify.rule=Host(`gotify.dominio.com`)
        - traefik.http.routers.gotify.tls.certresolver=letsencryptresolver
        - traefik.http.routers.gotify.entrypoints=websecure
        - traefik.http.services.gotify.loadbalancer.server.port=80

volumes:
  gotify-data:
networks:
  externa:
    external: true
```

### Integração com MNO
- **Traefik**: Labels padrão MNO para SSL automático
- **ntfy**: Alternativa — Gotify tem app Android nativo, ntfy tem app multiplataforma
- **Diferencial**: Gotify tem WebSocket nativo + Android app oficial
- **Complemento**: Não substitui ntfy — serve como alternativa para quem prefere interface de mensagens

### Comparação ntfy vs Gotify

| Feature | ntfy | Gotify |
|---------|------|--------|
| App Android | Sim | Sim |
| App iOS | Sim | Não |
| App Desktop | Sim | Não (web) |
| WebSocket | Sim | Sim |
| Autenticação | Basic auth | Token-based |
| Plugins | Não | Sim |
| Tamanho image | ~15MB | ~30MB |
| Multi-topics | Sim | Sim (apps) |

### Recomendação para MNO
**BAIXA PRIORIDADE**. ntfy já atende melhor (multiplataforma). Gotify é alternativa para quem quer app Android dedicado. Pode ser ofrecido como opção no menu.

## 5. Healthchecks.io (Cron Monitoring)

### Docker Image
- `lscr.io/linuxserver/healthchecks:latest` (porta 8000)
- Alternativa oficial: `healthchecks/healthchecks:latest`

### Como Funciona
Healthchecks é um watchdog para cron jobs. Cron jobs enviam "pings" em cada execução. Se um ping não chega dentro do prazo esperado, dispara alerta.

### Docker Swarm Stack YAML
```yaml
version: "3.7"
services:
  healthchecks:
    image: lscr.io/linuxserver/healthchecks:latest
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=UTC
      - SECRET_KEY=chave-secreta-aqui
      - SITE_ROOT=https://healthchecks.dominio.com
      - SITE_NAME=MNO HealthChecks
      - SUPERUSER_EMAIL=admin@dominio.com
      - SUPERUSER_PASSWORD=senha
    volumes:
      - healthchecks-data:/config
    networks:
      - externa
    deploy:
      mode: replicated
      replicas: 1
      placement:
        constraints:
          - node.role == manager
      labels:
        - traefik.enable=true
        - traefik.http.routers.healthchecks.rule=Host(`health.dominio.com`)
        - traefik.http.routers.healthchecks.tls.certresolver=letsencryptresolver
        - traefik.http.routers.healthchecks.entrypoints=websecure
        - traefik.http.services.healthchecks.loadbalancer.server.port=8000

volumes:
  healthchecks-data:
networks:
  externa:
    external: true
```

### Integração com MNO
- **Crons do MNO**: Monitorar `setup-mno.sh`, updates automáticos, backups
- **n8n workflows**: n8n pode enviar pings para Healthchecks antes e depois de workflows críticos
- **PostgreSQL**: Cron de backup pode pingar Healthchecks
- **ntfy**: Healthchecks pode alertar via ntfy (webhook customizado)
- **Docker Swarm**: Usar Docker health checks para manter containers healthy

### Casos de Uso no MNO
```bash
# Exemplo: monitorar cron de backup
# No crontab do host:
0 2 * * * /root/backup.sh && curl -s https://health.dominio.com/ping/abc123 || true
```

### Recomendação para MNO
**ALTA PRIORIDADE**. Ferramenta leve e essencial para monitorar a saúde dos cron jobs do próprio MNO. Pode ser incluída nos "essenciais" do setup.

## 6. Netdata (Real-Time Monitoring)

### Docker Image
- `netdata/netdata` (porta 19999)
- Tags: `stable`, `edge`, `latest`

### Como Funciona
Netdata coleta métricas em tempo real (1 segundo) de CPU, memória, disco, rede, containers Docker, processos. Dashboard web com gráficos ao vivo.

### Docker Swarm Stack YAML
```yaml
version: "3.7"
services:
  netdata:
    image: netdata/netdata:stable
    pid: host
    network_mode: host
    cap_add:
      - SYS_PTRACE
      - SYS_ADMIN
    security_opt:
      - apparmor:unconfined
    volumes:
      - netdataconfig:/etc/netdata
      - netdatalib:/var/lib/netdata
      - /proc:/host/proc:ro
      - /sys:/host/sys:ro
      - /etc/os-release:/host/etc/os-release:ro
      - /var/run/docker.sock:/var/run/docker.sock:ro
    deploy:
      mode: global

volumes:
  netdataconfig:
  netdatalib:
```

### Integração com MNO
- **Grafana**: Netdata pode exportar métricas via Prometheus remote write
- **Docker socket**: Monitora todos os containers do Swarm automaticamente
- **Traefik**: Coleta métricas do Traefik via API
- **Portainer**: Containers visíveis no dashboard Netdata

### Limitações no Swarm
- Requer `pid: host` e `network_mode: host` — **não é compatível com Docker Swarm mode padrão**
- Deve rodar como container standalone OU com `deploy.mode: global` + `pid: host`
- Não pode ser exposto via Traefik facilmente (precisa de host network)

### Recomendação para MNO
**MÉDIA PRIORIDADE**. Útil mas tem limitações de compatibilidade com Swarm. Alternativa ao Grafana/Prometheus existente para quem quer dashboards real-time mais granulares. Conflita parcialmente com Grafana/Prometheus.

## 7. Beszel (Lightweight Server Monitoring)

### Docker Images
- **Hub**: `henrygd/beszel` (porta 8090)
- **Agent**: `henrygd/beszel-agent` (porta 45876)
- 23.5k stars, MIT license, ~12MB agent image

### Como Funciona
Beszel é um platform de monitoramento leve baseado em PocketBase. Arquitetura hub + agent: o hub coleta métricas via WebSocket dos agents. Inclui Docker stats, alertas, multi-usuário, OAuth.

### Docker Swarm Stack YAML
```yaml
version: "3.7"
services:
  beszel-hub:
    image: henrygd/beszel:latest
    volumes:
      - beszel-data:/beszel_data
    networks:
      - externa
    deploy:
      mode: replicated
      replicas: 1
      placement:
        constraints:
          - node.role == manager
      labels:
        - traefik.enable=true
        - traefik.http.routers.beszel.rule=Host(`beszel.dominio.com`)
        - traefik.http.routers.beszel.tls.certresolver=letsencryptresolver
        - traefik.http.routers.beszel.entrypoints=websecure
        - traefik.http.services.beszel.loadbalancer.server.port=8090

  beszel-agent:
    image: henrygd/beszel-agent:latest
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
    networks:
      - interna
    deploy:
      mode: global
    environment:
      - PORT=45876
      - KEY=chave-publica-ed25519

volumes:
  beszel-data:
networks:
  externa:
    external: true
  interna:
    external: true
```

### Integração com MNO
- **Traefik**: Labels padrão para SSL automático
- **Docker socket**: Agent coleta stats de todos os containers automaticamente
- **ntfy**: Beszel suporta notificações via webhook (integrável com ntfy)
- **Grafana**: Beszel é independente — não precisa do Grafana
- **Portainer**: Deploy via stack YAML upload
- **Multi-servidor**: Hub pode monitorar agents em múltiplos VPS

### Vantagens vs Grafana/Prometheus
| Feature | Grafana/Prometheus | Beszel |
|---------|-------------------|--------|
| Setup complexity | Alta (4 containers) | Baixa (1 hub + 1 agent) |
| Docker stats | Via cAdvisor | Nativo |
| Memória | ~1GB+ | ~50MB |
| Alertas | Via Alertmanager | Nativo |
| Interface | Grafana (poderosa) | Simples e direta |

### Recomendação para MNO
**ALTA PRIORIDADE**. Beszel é ideal para o público MNO: leve, simples, bonito, multi-servidor. Pode substituir ou complementar o Grafana/Prometheus para monitoramento básico de server. Excelente para criadores de cursos que querem ver se o VPS está saudável.

## 8. Gatus (Health Dashboard)

### Docker Image
- `twinproduction/gatus:stable` (porta 8080)
- Alternativa: `ghcr.io/twin/gatus:stable`
- 11.5k stars, Apache-2.0

### Como Funciona
Gatus é um health dashboard que monitora endpoints via HTTP, ICMP, TCP, DNS. Avalia condições (status code, response time, body content) e envia alertas. Suporta Slack, Telegram, ntfy, Gotify, PagerDuty, Discord, etc.

### Docker Swarm Stack YAML
```yaml
version: "3.7"
services:
  gatus:
    image: twinproduction/gatus:stable
    volumes:
      - gatus-config:/config
    networks:
      - externa
      - interna
    deploy:
      mode: replicated
      replicas: 1
      placement:
        constraints:
          - node.role == manager
      labels:
        - traefik.enable=true
        - traefik.http.routers.gatus.rule=Host(`status.dominio.com`)
        - traefik.http.routers.gatus.tls.certresolver=letsencryptresolver
        - traefik.http.routers.gatus.entrypoints=websecure
        - traefik.http.services.gatus.loadbalancer.server.port=8080

volumes:
  gatus-config:
networks:
  externa:
    external: true
  interna:
    external: true
```

### Configuração de Endpoints
```yaml
# /config/config.yaml
endpoints:
  - name: n8n
    url: "https://n8n.dominio.com/healthz"
    interval: 1m
    conditions:
      - "[STATUS] == 200"
      - "[RESPONSE_TIME] < 3000"
    alerts:
      - type: ntfy
        url: "https://ntfy.dominio.com/mno-alertas"
        priority: high

  - name: grafana
    url: "https://grafana.dominio.com/api/health"
    interval: 1m
    conditions:
      - "[STATUS] == 200"

  - name: postgres
    url: "tcp://postgres:5432"
    interval: 30s
    conditions:
      - "[CONNECTED] == true"
```

### Integração com MNO
- **ntfy**: Gatus suporta ntfy nativamente como alert provider
- **Traefik**: Labels padrão MNO
- **PostgreSQL**: Monitorar conectividade TCP
- **n8n**: Health check endpoint disponível
- **Uptime Kuma**: Gatus complementa — Gatus é mais focado em health checks com condições avançadas

### Gatus vs Uptime Kuma

| Feature | Gatus | Uptime Kuma |
|---------|-------|-------------|
| Health checks | HTTP, TCP, ICMP, DNS, SSH | HTTP, TCP, Ping, Docker |
| Condições | Avançadas (body, response time, cert) | Básicas |
| Alerting | 25+ providers (incl. ntfy, Gotify) | 80+ notificações |
| Dashboard | Minimalista, funcional | Bonito, moderno |
| Storage | SQLite/PostgreSQL | SQLite |
| Status page | Sim (público) | Sim (público) |
| Docker stats | Não | Não |

### Recomendação para MNO
**ALTA PRIORIDADE**. Gatus complementa Uptime Kuma: Gatus para health checks programáticos com condições, Uptime Kuma para monitoring de uptime visual. Pode ser ofrecido como combo "Status Page" com ambos.

## 9. Diun (Docker Image Update Notifier)

### Docker Image
- `crazymax/diun:latest`
- 4.8k stars, MIT, ~10MB

### Como Funciona
Diun monitora registries Docker e notifica quando uma imagem tem nova tag ou digest. Pode monitorar imagens do Docker Hub, GHCR, registries privados.

### Docker Swarm Stack YAML
```yaml
version: "3.7"
services:
  diun:
    image: crazymax/diun:latest
    command: serve
    volumes:
      - diun-data:/data
      - /var/run/docker.sock:/var/run/docker.sock:ro
    environment:
      - TZ=UTC
      - DIUN_WATCH_WORKERS=20
      - DIUN_WATCH_SCHEDULE=0 */6 * * *
      - DIUN_PROVIDERS_DOCKER=true
      - DIUN_PROVIDERS_DOCKER_WATCHBYDEFAULT=true
      - DIUN_NOTIF_NTFY_ENDPOINT=https://ntfy.dominio.com
      - DIUN_NOTIF_NTFY_TOPICS=mno-updates
    networks:
      - interna
    deploy:
      mode: replicated
      replicas: 1
      placement:
        constraints:
          - node.role == manager

volumes:
  diun-data:
networks:
  interna:
    external: true
```

### Integração com MNO
- **Docker socket**: Monitora todas as imagens em uso no Swarm
- **ntfy**: Diun suporta ntfy nativamente como notificador
- **Traefik**: Pode monitorar atualizações do Traefik
- **Todas as apps**: Diun alerta quando qualquer imagem tem update disponível
- **Uso crítico**: Para 65+ apps do MNO, Diun é essencial para manter tudo atualizado

### Recomendação para MNO
**ALTA PRIORIDADE**. Essencial para manter 65+ apps atualizadas. Pode ser incluído como "essencial" do setup. Alerta via ntfy quando imagens têm updates de segurança.

## 10. CrowdSec (Collaborative Security)

### Docker Image
- **CrowdSec**: `crowdsecurity/crowdsec:latest`
- **Traefik Bouncer**: `crowdsecurity/traefik-bouncer:latest`

### Como Funciona
CrowdSec é um IDS/IPS colaborativo. Analisa logs, detecta comportamento malicioso, e compartilha blocklists com a comunidade. O Traefik Bouncer bloqueia IPs maliciosos em tempo real.

### Docker Swarm Stack YAML
```yaml
version: "3.7"
services:
  crowdsec:
    image: crowdsecurity/crowdsec:latest
    volumes:
      - crowdsec-config:/etc/crowdsec
      - crowdsec-data:/var/lib/crowdsec
      - /var/log:/var/log:ro
      - /var/run/docker.sock:/var/run/docker.sock:ro
    environment:
      - COLLECTIONS=crowdsecurity/traefik crowdsecurity/linux
      - GEEKOUuid=your-uuid-here
    networks:
      - interna
    deploy:
      mode: replicated
      replicas: 1
      placement:
        constraints:
          - node.role == manager

  traefik-bouncer:
    image: crowdsecurity/traefik-bouncer:latest
    environment:
      - CROWDSEC_BOUNCER_API_KEY=your-api-key
      - CROWDSEC_BOUNCER_HOST=crowdsec:8080
    networks:
      - interna
    deploy:
      mode: global

volumes:
  crowdsec-config:
  crowdsec-data:
networks:
  interna:
    external: true
```

### Integração com MNO
- **Traefik**: Bouncer plugin do Traefik bloqueia IPs automaticamente
- **ntfy**: CrowdSec pode alertar via webhook para ntfy
- **Logs**: CrowdSec analisa logs do Traefik para detectar ataques
- **Docker socket**: Monitora containers para detecção de anomalias
- **Blocklist**: Contribui e recebe blocklists da comunidade

### Recomendação para MNO
**MÉDIA-ALTA PRIORIDADE**. Segurança colaborativa é valiosa para VPS expostos na internet. Requer configuração cuidadosa para não afetar performance do Traefik. Pode ser ofrecido como add-on de segurança.

## 11. Wazuh (Security Monitoring / SIEM)

### Docker Image
- `wazuh/wazuh-docker:latest` (4.11+)
- Componentes: wazuh-manager, wazuh-indexer, wazuh-dashboard
- Requer: OpenSearch-compatible indexer

### Como Funciona
Wazuh é um SIEM completo: detecção de intrusão, conformidade, integridade de arquivos, vulnerabilidades. Oferece dashboard dedicado, regras customizáveis, e integração com MITRE ATT&CK.

### Docker Swarm Considerações
```yaml
# ATENÇÃO: Wazuh é complexo para Docker Swarm
# Requer 3+ containers com configuração específica:
# 1. wazuh-manager (4GB RAM mínimo)
# 2. wazuh-indexer (4GB RAM mínimo)  
# 3. wazuh-dashboard (2GB RAM mínimo)
# Total: ~10GB RAM mínimo para Wazuh sozinho
```

### Integração com MNO
- **Traefik**: Pode monitorar logs do Traefik para detecção de ataques
- **PostgreSQL**: Monitor de integridade de dados
- **Docker**: Wazuh agent pode monitorar containers
- **Grafana**: Não integra nativamente (Wazuh tem dashboard próprio)
- **ntfy**: Via webhook customizado

### Limitações para MNO
- **Memória**: ~10GB RAM mínimo (muito para VPS típico do MNO)
- **Complexidade**: Setup extremamente complexo para Swarm
- **Manutenção**: Requer atualizações frequentes de regras
- **Público**: Muito avançado para criadores de cursos

### Recomendação para MNO
**BAIXA PRIORIDADE**. Wazuh é overkill para o público MNO. CrowdSec atende melhor com menos overhead. Pode ser documentado como opção para usuários avançados/enterprise.

| **Netdata** | Real-time monitoring (conflita com Grafana) | ~200MB |
| **Gotify** | Push notifications (ntfy já atende) | ~64MB |

### Tier 4 — Não recomendado para MNO
| Ferramenta | Justificativa |
|-----------|---------------|
| **Wazuh** | Overkill: ~10GB RAM, complexo, público inadequado |

## Combos Pré-Integrados Sugeridos

### Combo "Monitoring Essential" (Free)
- **Grafana** (já existe) + **Loki** + **Diun** + **Gatus**
- Uso: logs centralizados + updates monitorados + health checks
- RAM adicional: ~400MB

### Combo "DevOps Pro" (Pro)
- **Beszel** + **Healthchecks** + **CrowdSec** + **ntfy** (hub)
- Uso: server monitoring + cron monitoring + segurança + notificações
- RAM adicional: ~500MB

### Combo "Full Observability" (Pro)
- **Grafana** + **Loki** + **Tempo** + **Gatus** + **Beszel**
- Uso: métricas + logs + traces + health + server monitoring
- RAM adicional: ~1GB

## Padrões de Deploy no MNO

### Padrão Traefik Labels (x86)
```yaml
labels:
  - traefik.enable=true
  - traefik.http.routers.APP.rule=Host(`app.dominio.com`)
  - traefik.http.routers.APP.tls.certresolver=letsencryptresolver
  - traefik.http.routers.APP.entrypoints=websecure
  - traefik.http.services.APP.loadbalancer.server.port=PORT
```

### Padrão Deploy Swarm
```yaml
deploy:
  mode: replicated
  replicas: 1
  placement:
    constraints:
      - node.role == manager
  resources:
    limits:
      cpus: "0.5"
      memory: 512M
```

### Padrão Portainer Stack
Todos os combos devem ser empacotáveis como YAML para upload via Portainer API, seguindo o padrão existente nos scripts `grafana.sh`, `ntfy.sh`, `dozzle.sh`.
