Vibe Ops BETA Exclusivo PRO & PRO MASTER

Vibe Ops & MNO Fleet Hub

A arquitetura moderna do Setup MNO para orquestrar múltiplos servidores em nuvem com Zero Portas Abertas, criptografia ponta a ponta e 0 MB de consumo ocioso.

Requisitos Obrigatórios para Ativação:
  • ☁️ Apenas em VPS: Servidores em nuvem pública (Debian/Ubuntu x86 ou ARM) com conexão 24/7. (WSL2 funciona apenas como laboratório local standalone).
  • 🛡️ Modo Cloudflare Tunnel: Toda a federação se comunica por túneis seguros ou WireGuard mesh, com Zero Portas Abertas no firewall para invasores.
  • 👑 Planos PRO ou PRO MASTER: Gestão de frota multi-servidor é um recurso avançado e corporativo disponível para assinantes PRO e PRO MASTER.

Os 3 Modos de Operação Explicados:

Modo Simples Standalone (Desativado / Padrão)

Padrão e Seguro (0 MB de RAM): O servidor opera individualmente com 100% dos recursos do Setup MNO. Ideal para quem tem uma VPS e não precisa de multi-servidor. Não consome nada de memória ociosa.

Modo Torre Master (Controlador Central)

Cérebro da Frota: Centraliza a visão dos servidores, agrega memória RAM total combinada, latência em tempo real e orquestra os nós operários subordinados.

Modo Nó Operário (Subordinado de Cargas)

Operário Subordinado: Servidor secundário (VPS ou laboratório) que executa containers e cargas sem precisar de painel web local, pareado via token criptográfico seguro.

03Pedir ajuda ao Assistente MNOQuando usar o modo Básico ou uma LLM.＋
  1. Para uma resposta rápida, clique em Analisar a saúde do servidor. O Assistente usa uma fotografia sanitizada de recursos, réplicas e sinais permitidos.
  2. Para verificar segurança com mais profundidade, clique em Analisar segurança agora, redigite a senha e confirme uma única vez. O Setup executa Trivy, Lynis e Docker Bench somente em leitura.
  3. Quando terminar, volte ao Assistente e peça Faça uma revisão de segurança do servidor. A resposta traduz os achados e separa fatos, hipóteses e próximos passos.
  4. O Trivy procura vulnerabilidades conhecidas nas imagens das aplicações; o Lynis revisa a configuração do Linux; o Docker Bench compara o Docker com práticas reconhecidas.
  5. Leia primeiro o resumo simples. Abra detalhes técnicos apenas se precisar investigar a origem de uma cobertura parcial ou de um alerta.
  6. O plano consultivo e o runbook explicam impacto, evidências pendentes, validação e rollback. Eles não executam correções.
  7. Em instalação Tradicional, execute por SSH sudo bash /root/SetupLowCodeMno/.control/sre-engine/run.sh.

⎇Dominar o Vibe Ops e o MNO Fleet Hub [BETA]Requisitos, modos de operação e passo a passo para conectar e gerenciar múltiplos servidores.＋
O que é o Vibe Ops no Setup MNO? Vibe Ops é a engenharia de infraestrutura ágil e moderna criada pelo Setup MNO: sem painéis web gigantescos gastando 2 GB de memória ociosa (como Coolify ou Portainer). Uma arquitetura enxuta, orquestrada por Docker Swarm, com Zero Portas Abertas via Cloudflare Tunnel e 0 MB de consumo de memória enquanto desativada.

Requisitos Mandatórios:

  1. Apenas em Servidores VPS: Exige servidores virtuais na nuvem (Hetzner, Contabo, DigitalOcean, Oracle ARM, etc.) com conectividade contínua 24/7. O WSL2 no Windows é apenas laboratório local de estudos e não pode operar como nó remoto.
  2. Apenas no Modo Cloudflare Tunnel: Exige a instalação com Cloudflare Tunnel para manter Zero Portas Abertas no firewall. Instalações Tradicionais (com porta 80/443 expostas) não suportam a federação Zero-Trust.
  3. Planos PRO e PRO MASTER: O MNO Fleet Hub é um recurso corporativo avançado exclusivo para assinantes dos planos PRO e PRO MASTER.

🚀MNO Fleet Hub — Clone, Transferência e Backup Universal [BETA]Instruções detalhadas para mover, clonar, criar backups portáteis e restaurar combos em qualquer servidor.＋
O que é o Fleet Clone Universal no Setup MNO? É a tecnologia de ponta para mover aplicações e ecossistemas inteiros entre servidores (Torre Master e VPSs remotas) com Zero Portas Abertas no firewall. Ele realiza dumps lógicos consistentes de bancos de dados (sem risco de corromper tabelas InnoDB), captura todos os volumes persistentes de dados e comuta o DNS no Cloudflare Tunnel automaticamente em segundos.

Os 5 Modos de Operação Explicados (Menu Interativo fleet-clone.sh):

  1. 1. Raio-X da Frota (Hardware & Resource Preflight):

    Antes de mover qualquer byte, o sistema examina minuciosamente a arquitetura do processador (x86_64 vs arm64), a memória RAM livre, o espaço livre em disco e as stacks ativas em todos os servidores da frota. Se o destino não tiver recursos suficientes ou se houver incompatibilidade física, o sistema bloqueia preventivamente e protege você contra travamentos.

  2. 2. Transferir Aplicação para outro Servidor (Com migração de DNS Cloudflare):

    Ideal para troca definitiva de VPS ou balanceamento de carga. O Setup MNO faz o snapshot dos volumes e o dump lógico atômico do banco de dados na origem, envia pelo túnel criptografado para o destino, sobe a stack no Docker Swarm e comuta o DNS CNAME na Cloudflare para o novo servidor. Na origem, a stack antiga é desligada para liberar 100% da RAM e os volumes são congelados no disco com o sufixo de segurança _frozen_pre_transfer_<datahora> para permitir rollback imediato se necessário.

  3. 3. Clonar Aplicação para Teste (Sem alterar DNS da internet):

    Cria uma cópia idêntica da aplicação e dos dados no servidor de destino para você testar atualizações, novos plugins ou homologações. O DNS original de produção na Cloudflare permanece 100% intacto apontando para o servidor principal, garantindo risco zero para seus clientes.

  4. 4. Criar Backup Portátil (.tar.gz compatível com qualquer arquitetura):

    Gera uma verdadeira "Cápsula do Tempo" autossuficiente salva em /root/backup_fleet/. Contém o manifesto enriquecido (schemaVersion 2), os arquivos de stack YAML, os snapshots compactados de volumes Docker persistentes (volumes/vol_<nome>.tar.gz) e os dumps lógicos dos bancos de dados (PostgreSQL, MySQL 8.0, MySQL 8.4 ou MongoDB). Pode ser baixado e restaurado em qualquer servidor do mundo.

  5. 5. Restaurar Backup Portátil em um Servidor (Local ou Remoto via SSH):

    O motor de reconstrução em 1 clique. Você escolhe o arquivo .tar.gz de backup e o servidor de destino (local ou VPS remota da frota). O Setup MNO valida os recursos, provisiona automaticamente bancos ou dependências ausentes (Postgres, MySQL, MinIO, RabbitMQ), restaura os volumes com permissões corretas, faz o deploy no Swarm e abre o diálogo de intenção de DNS:

    • 🚨 Recuperação de Desastre (Disaster Recovery): Comuta imediatamente o Cloudflare Tunnel e o DNS para a nova máquina, colocando seu negócio de volta ao ar após queima ou perda da VPS antiga.
    • 🧪 Ambiente de Homologação (Clone): Mantém o DNS de produção intocado e ensina como testar o backup com segurança.
Detecção Inteligente de Combos e Política de Storage S3 (MinIO): Quando uma ferramenta faz parte de um combo (ex: chatwoot_f0e026b conectado à Evolution API, RabbitMQ e MinIO), o Fleet Clone reconhece automaticamente todas as ferramentas irmãs pelo sufixo compartilhado. Ele pergunta se você deseja MIGRAR O COMBO COMPLETO (recomendado) ou apenas a ferramenta isolada.

Por que o MinIO é tratado de forma especial? Aplicações de atendimento e WhatsApp gravam links completos públicos das fotos e áudios no banco de dados. Se o MinIO fosse misturado com outro domínio, todas as mídias históricas quebrariam. O Setup MNO resolve isso criando uma nova instância MinIO isolada no Swarm do destino com o mesmo domínio e credenciais (sem colisão de portas graças ao Traefik), ou mantendo o MinIO online 24/7 na origem com trava de desligamento inviolável!

Diagnóstico orientado

Quando algo não funciona

Comece pelo sintoma visível e avance sem apagar dados.

0/1

Aplicação “Com atenção”

  1. Confirme RAM e disco na Visão geral.
  2. Identifique a stack e o serviço afetado.
  3. Peça ao Assistente um roteiro de diagnóstico.
  4. Consulte logs pelo Portainer ou terminal.

Não remova o volume para “tentar de novo”. Ele pode conter os dados da aplicação.

DNS

A URL não abre

  1. NXDOMAIN: o hostname não possui DNS válido.
  2. Erro 502/504: DNS existe, mas o serviço de origem não respondeu.
  3. Certificado: confira se a nuvem está ativa e o modo SSL/TLS está correto.
  4. www: exige registro e rota próprios ou um redirecionamento que já possa ser alcançado por DNS.

No Tunnel, DNS e ingresso precisam apontar para o mesmo hostname. No modo Tradicional, confira DNS, Traefik e a porta 443.

WSL2

Docker não responde no Windows

  1. Abra o Docker Desktop e aguarde “Engine running”.
  2. Confirme que o backend WSL2 está habilitado.
  3. Em Resources > WSL Integration, habilite a distribuição Ubuntu usada.
  4. Feche e abra novamente o Ubuntu.
  5. Só então execute ou atualize o Setup MNO.

Se o Docker estiver desligado, interrompa a instalação. Não tente recriar o Swarm antes de restabelecer a integração.

LOGIN

Não consigo entrar

  1. Confirme se está na URL atual do Control Center.
  2. Conclua o Cloudflare Access quando ele estiver habilitado.
  3. Use o usuário e a senha administrativos do painel.
  4. Se a sessão expirou, autentique novamente.
  5. Para alterar a credencial, use Configurações Seguras.

Não envie senha, token de API ou código MFA em capturas de tela e mensagens de suporte.

FROTA

Falha ao migrar ou restaurar

  1. Arquitetura: Se a origem for x86 e o destino for ARM (ou vice-versa), use a Opção 4 (Backup Portátil .tar.gz).
  2. Recursos: Confirme se o destino possui RAM livre (mínimo da stack) e disco (1.2x do volume).
  3. SSH: Em nós remotos, confira a conectividade SSH e a chave autorizada em /root/.ssh/.
  4. Logs: Inspecione o log detalhado em /tmp/fleet-transfer.log.

Seus dados estão protegidos: a stack e os volumes da origem nunca são apagados e ficam congelados para rollback.

Glossário essencial

Palavras parecidas representam objetos diferentes.

Aplicação
O produto ou software, como N8N, WordPress ou Uptime Kuma.
Setup
Uma configuração instalável. A mesma aplicação pode ter variantes e aparecer em combos diferentes.
Stack
Conjunto implantado no Docker Swarm, formado por um ou mais serviços.
Serviço
Unidade executada pelo Swarm com imagem, rede, volumes, limites e quantidade de réplicas.
Blueprint
Receita orientada a um resultado, combinando setups, ordem, integrações, validações e rollback.
Beta
Funcionalidade disponível para testes controlados, mas ainda em amadurecimento. Pode mudar e seus limites devem ser lidos antes do uso.
Selo de Homologação
Evidência de que uma versão passou pelos gates definidos. Não significa que qualquer combinação futura está automaticamente aprovada.
Fleet Clone
Motor inteligente do MNO Fleet Hub para migrar, clonar, empacotar e restaurar aplicações e combos inteiros entre servidores.
Backup Portátil (.tar.gz)
Cápsula independente contendo manifesto schemaVersion 2, stacks YAML, volumes compactados e dumps lógicos de bancos, restaurável em qualquer servidor.
Dump Lógico
Exportação estruturada e atômica dos dados do banco (PostgreSQL, MySQL ou MongoDB) que evita corrupção física durante transferências.
Comutação de DNS
Atualização automática do apontamento CNAME no Cloudflare Tunnel para redirecionar o domínio público para o novo servidor em segundos.

Perguntas frequentes

Respostas rápidas

O Control Center instala aplicações sozinho?＋

Não. Ele abre o Instalador Seguro e apresenta informações. O usuário continua responsável por escolher, revisar e confirmar as operações.

O Assistente MNO executa comandos no servidor?＋

Não. Ele é consultivo: analisa informações permitidas e sugere verificações. Não possui shell, Docker socket nem ferramenta de escrita.

Se eu fechar o navegador, a instalação para?＋

Uma operação já iniciada no tmux pode continuar. Autentique-se novamente e retome a sessão. Se o instalador ainda aguardava uma resposta, volte antes do timeout.

Atualizar o Setup MNO apaga minhas aplicações?＋

O fluxo de atualização foi desenhado para reconciliar o Setup e preservar recursos existentes. Ainda assim, mantenha backups e leia todas as confirmações antes de qualquer operação administrativa.

Por que “setups” não significa “aplicações únicas”?＋

Porque o catálogo conta opções instaláveis. Variantes, versões e combos podem usar a mesma aplicação em configurações diferentes.

O que significa a etiqueta BETA?＋

Significa que o recurso já pode ser testado, mas ainda está sendo amadurecido e pode mudar. Leia os limites exibidos e não confunda Beta com homologação completa. “Em breve” indica algo que ainda não está disponível.

O que é o MNO Fleet Hub e quanto ele consome?＋

O MNO Fleet Hub é o motor do Vibe Ops no Setup MNO, permitindo conectar vários servidores a uma Torre de Controle central com Zero Portas Abertas. No modo Simples Padrão (desativado), ele consome exatamente 0 MB de RAM. Quando ativado como Torre Master ou Nó Operário, seu daemon Go ultraenxuto consome menos de 15 MB de RAM.

Quais os requisitos mandatórios para usar o MNO Fleet Hub (Vibe Ops)?＋

Para ativar a federação multi-servidor, são obrigatórios três critérios: 1) Instalação no modo Cloudflare Tunnel (Zero Portas Abertas no firewall); 2) Licença PRO ou PRO MASTER ativa; 3) Para Nós Operários de produção 24/7, recomenda-se VPS na nuvem pública. A Torre Master opera perfeitamente tanto em VPS quanto localmente no Windows com WSL2. No plano Free ou modo Tradicional, a funcionalidade permanece indisponível.

Meu servidor mostra "Modo Simples (Desativado)". Isso é um erro?＋

Não! De maneira alguma. O Modo Simples Standalone é a configuração padrão mais rápida, estável e segura do Setup MNO. Ele garante que seu servidor dedique 100% da CPU e da memória RAM para as suas aplicações e automações, sem gastar absolutamente nada (0 MB de sobrecarga) com comunicação multi-servidor se você tiver apenas uma VPS.

Posso usar a Federação Multi-VPS no WSL2 (Windows)?＋

Sim, tanto como Torre Master quanto como Nó Operário! Como Torre Master no WSL2, seu computador pessoal funciona como o Centro de Comando para gerenciar seus servidores remotos (Nós Operários) com conexões seguras de saída e zero portas abertas no roteador doméstico. Como Nó Operário no WSL2, você pode executar testes e aplicações subordinados à sua Torre, ciente de que se a conexão oscilar, a tampa do notebook for fechada ou o PC desligado, as aplicações deste nó ficarão indisponíveis.

O que é o Fleet Clone Universal e como ele difere de um backup comum?＋

O Fleet Clone não é uma simples cópia de arquivos. Ele é um motor orquestrado de migração que realiza dumps lógicos consistentes de bancos de dados (PostgreSQL, MySQL 8.0/8.4, MongoDB) para evitar corrupção de tabelas InnoDB, empacota todos os volumes Docker persistentes (fotos, áudios, anexos) e realiza a comutação automática de DNS Cloudflare. Tudo isso com Zero Portas Abertas no firewall e 0 MB de consumo ocioso.

Como funciona a detecção inteligente de Combos (Chatwoot, Evolution, MinIO)?＋

Quando você instala um combo no Setup MNO, o sistema gera um sufixo exclusivo (ex: f0e026b). Ao solicitar uma transferência ou backup, o Fleet Clone rastreia todas as stacks que compartilham o mesmo sufixo e pergunta se você deseja Migrar o Combo Completo (mantendo Chatwoot, Evolution, RabbitMQ e MinIO juntos) ou Apenas a Aplicação Isolada, garantindo integridade absoluta.

Por que o Setup MNO isola o MinIO S3 em vez de misturar com outro bucket?＋

Aplicações como Chatwoot e Evolution gravam no banco de dados o link completo público das fotos e áudios do WhatsApp (ex: https://s3.cliente.com.br/...). Se o Setup MNO tentasse misturar arquivos em um MinIO existente com outro domínio, todas as conversas antigas perderiam as fotos e áudios. Por isso, criamos uma nova instância isolada no Docker Swarm com o mesmo domínio e credenciais. Como usamos Traefik e Cloudflare Tunnel, não há colisão de portas e 100% das mídias históricas continuam abrindo perfeitamente!

Como restaurar uma aplicação se a VPS antiga queimar (Disaster Recovery)?＋

Basta levar o arquivo .tar.gz gerado no backup para a sua nova VPS (ou salvar em /root/backup_fleet/) e executar a Opção 5 (Restaurar Backup Portátil) no terminal. O assistente perguntará se a restauração é para Recuperação de Desastre (Disaster Recovery). Ao confirmar, ele sobe todos os bancos, restaura os volumes e atualiza instantaneamente o Cloudflare Tunnel para que seu site volte ao ar na nova máquina em minutos.

Posso transferir aplicações ao vivo entre servidores x86 e ARM?＋

Por segurança rígida, a transferência ao vivo de containers é bloqueada entre chips diferentes (ex: Intel/AMD x86 para Oracle/ARM), pois imagens compiladas para uma arquitetura travam na outra. No entanto, o Setup MNO autoriza e recomenda a Opção 4: Backup Portátil (.tar.gz). Como o backup portátil salva os dados e bancos puros, você pode restaurá-lo em qualquer arquitetura sem risco de travamento.

O que acontece com os dados no servidor antigo após a transferência?＋

Na transferência com sucesso, a stack antiga é desligada para liberar 100% da memória RAM e evitar conflitos de gravação. Seus dados e volumes NUNCA são apagados: eles são congelados no disco com o sufixo _frozen_pre_transfer_<datahora>. Se você quiser desfazer a migração (Rollback), basta reverter o nome do volume e religar a stack.

Como alterno entre modo claro e escuro?＋

Use o botão de sol ou lua ao lado de Novo deploy. O modo escuro continua sendo o padrão; sua escolha fica salva somente neste navegador. No desktop, os textos auxiliares também usam letras maiores. O Terminal Seguro permanece escuro para preservar a leitura e a aparência real do terminal.

O que devo enviar ao suporte?＋

Informe a versão, o ambiente, a etapa, a mensagem exata e o horário aproximado. Envie apenas trechos de log sem senhas, tokens, cookies, chaves ou dados pessoais.
