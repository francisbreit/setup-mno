# v7.34.2 candidata — handoff seguro após o login do bootstrap

- Data: 26/08/2026
- Estado documental: `implemented`
- Maturidade da correção: `stable`
- Release: candidata, ainda não promovida a estável
- Público: todos os planos
- Ambientes: WSL2 e VPS, x86_64 e ARM64

## Para iniciantes

O arquivo público que inicia o Setup MNO funcionava como uma recepção: ele
baixava o instalador protegido e aguardava o resultado do login. Foi confirmado
que os dois arquivos publicados possuíam um segundo rodapé anexado por engano.
Quando a senha era recusada, a recepção continuava lendo esse trecho quebrado e
mostrava “O arquivo não é executável” seguido de erro de sintaxe.

A v7.34.2 faz uma entrega definitiva: depois de baixar e validar o instalador,
o bootstrap é substituído pelo processo protegido. É como entregar a chave ao
responsável e encerrar o expediente da recepção. Se o login falhar ou for
cancelado, o código devolvido pelo instalador encerra a operação sem executar
mais nada do bootstrap.

## O que mudou

- `setup-mno.sh` e `setup-mno-oracle.sh` usam uma única função de handoff;
- o arquivo baixado deve ser regular e recebe permissão `0700` antes do uso;
- `exec` substitui o bootstrap pelo gatilho SHC e preserva seu código de saída;
- um teste automatizado simula senha incorreta e um rodapé inválido anexado;
- um gate pós-publicação baixa os bootstraps e exige igualdade byte a byte com
  os artefatos aprovados.

Permanecem iguais a autenticação, as credenciais, os planos, a proteção SHC, a
seleção x86/ARM, o instalador monolítico e os dados das aplicações. Nenhuma
senha é gravada, exibida ou enviada ao novo gate.

## O que o usuário verá

Com credenciais corretas, o fluxo segue normalmente. Com e-mail ou senha
incorretos, aparece somente a mensagem de login recusado; depois de confirmar,
o processo retorna ao terminal. As mensagens “O arquivo não é executável” e
“syntax error near unexpected token” não devem mais aparecer.

## Nota técnica para DevOps

O defeito publicado não existia nos arquivos locais aprovados: havia 25 linhas
extras no bootstrap padrão e 23 no Oracle. O Bash interpreta o arquivo em
blocos. Após o binário SHC retornar, o shell alcançava o segundo rodapé e então
o token órfão `else` ou `then` causava a falha.

O handoff `exec "./$installer"` elimina o caminho de retorno. O teste injeta
deliberadamente um `else` inválido após a chamada, usa um instalador fictício
que retorna `23` e exige simultaneamente: status `23`, ausência de continuação e
nenhum erro de sintaxe. O gate remoto ainda executa `bash -n` e `cmp` contra
`3_distribuicao/` para detectar anexação, truncamento ou substituição no upload.

## Como testar no WSL2

Pré-requisitos: Docker Desktop iniciado e distribuição WSL integrada. Nenhuma
credencial real é necessária para os gates locais.

```bash
bash 1_codigo_fonte/setupmno-control/bootstrap-handoff_test.sh
bash -n 1_codigo_fonte/setup-mno.sh
bash -n 1_codigo_fonte/setup-mno-oracle.sh
```

Resultado esperado: `BOOTSTRAP_HANDOFF_TESTS_OK` e código de saída zero.
Sinal de falha: mensagem de continuação indevida, status diferente de `23` ou
qualquer erro de sintaxe.

Depois de publicar os arquivos substituindo o conteúdo remoto por completo:

```bash
bash 1_codigo_fonte/setupmno-control/bootstrap-publication-gate.sh
```

Resultado esperado: dois `PUBLIC_BOOTSTRAP_OK` e
`PUBLIC_BOOTSTRAP_GATE_OK`. Qualquer diferença de byte ou sintaxe bloqueia a
declaração de publicação concluída.

## Como testar na VPS

Baixe o bootstrap em um diretório temporário e valide antes de executá-lo:

```bash
tmp_bootstrap=$(mktemp)
curl -fsSL https://ativa2.manualnegocioonline.com.br/setup-mno.sh -o "$tmp_bootstrap"
bash -n "$tmp_bootstrap"
rm -f "$tmp_bootstrap"
```

Resultado esperado: nenhum texto e código zero. Em seguida, um teste visual com
uma credencial fictícia inválida deve terminar após o aviso de login, sem a
mensagem de arquivo não executável.

## Riscos, limites e proteções

- o gate remoto confirma conteúdo e sintaxe, não confirma disponibilidade da
  API de autenticação;
- a correção não altera nem recupera senhas;
- um upload por anexação volta a ser detectado, mas precisa ser executado após
  cada publicação;
- a versão estável continua v7.33.4 até promoção explícita do mantenedor.

## Rollback

Se houver regressão antes da promoção, restaure os dois bootstraps e as versões
de `start_full`, `start_arm_full` e `install.sh` a partir do commit anterior,
regenere os pacotes e execute novamente os gates. Não remova stacks, volumes,
secrets, bancos ou a instalação de referência: a mudança afeta somente os
arquivos de início e os metadados da candidata.

## Como explicar para a comunidade

“Corrigimos a passagem do arquivo público para o instalador protegido. Agora,
quando o login termina — inclusive com senha errada — o bootstrap também
termina, sem cair em comandos duplicados. Além disso, o arquivo publicado é
comparado com o pacote aprovado para impedir que um upload incompleto passe
despercebido.”
