# v7.34.1 candidata — correção dos motores SRE no WSL2

- Estado documental: `implemented`
- Maturidade: `beta`
- Data: 25/08/2026
- Última versão estável preservada: `v7.33.4`

## Para iniciantes

Na v7.34.0, os três instrumentos da auditoria apareciam como `failed` no WSL2,
mesmo sem alterar aplicações. A v7.34.1 corrige a forma como cada instrumento é
iniciado. É como fornecer uma bancada do tamanho correto, abrir o manual na
pasta certa e direcionar o relatório para uma folha gravável.

Depois da correção, Trivy, Lynis e Docker Bench devem produzir contagens. Lynis
e Docker Bench ainda podem aparecer como `partial`: isso é esperado no WSL2 e
significa cobertura útil, porém limitada. `failed` continua significando que a
ferramenta não conseguiu concluir.

## Problemas corrigidos

- o Trivy não conseguia terminar o download da base porque o `/tmp` temporário
  de 128 MiB ficava sem espaço;
- o Lynis era iniciado fora de seu diretório e não encontrava a pasta
  `include`; além disso, precisava de um pequeno `/var/run` temporário;
- o Docker Bench tentava gravar seu log interno no código montado somente para
  leitura e classificava a execução como falha.

## O que mudou

- Trivy: `/tmp` efêmero de 512 MiB e limite de memória de 1 GiB apenas durante
  o download da base;
- Lynis: diretório de trabalho `/lynis`, `--usecwd` e `/var/run` efêmero de
  4 MiB;
- Lynis: contagem sanitizada da lista oficial `tests_executed` do relatório
  3.1.7, evitando exibir zero sem persistir os identificadores dos testes;
- Docker Bench: log interno em `/tmp` e etiqueta upstream
  `docker.bench.security=true`;
- testes de regressão bloqueiam o retorno das três configurações incorretas;
- Setup MNO `7.34.1` e Control Center `4.34.1`.

## O que permaneceu igual

- a funcionalidade continua BETA e somente leitura;
- nenhuma correção, reinício de aplicação ou alteração de configuração é feita;
- Trivy e Lynis continuam sem Docker socket;
- o host permanece montado somente para leitura;
- os achados brutos são apagados, e apenas contagens sanitizadas válidas por
  24 horas chegam ao Control Center;
- a v7.33.4 continua sendo a versão estável até nova declaração explícita.

## Teste no WSL2

Execute a auditoria pelo Terminal Seguro e valide o resumo:

```bash
sudo jq '{hostType,overallStatus,complete,engines:[.engines[]|{id,status,counts,limitations}]}' \
  /root/SetupLowCodeMno/.control/sre-engine/latest.json
```

Resultado esperado: `hostType` igual a `wsl2`; nenhum motor com status
`failed`; Trivy com pelo menos uma imagem; Lynis com testes; Docker Bench com
contagens. `complete:false` pode continuar correto quando a cobertura é
`partial` por segurança.

Sinal de falha: qualquer motor `failed`, Trivy com `images:0`, Lynis com
`tests:0` ou ausência do arquivo. Não envie achados brutos, nomes de imagens ou
credenciais ao suporte.

## Teste na VPS

Repita o mesmo fluxo em uma VPS Debian/Ubuntu. O resultado deve conter contagens
e nenhum `failed`. A classificação de cobertura pode ser diferente do WSL2,
pois uma VPS possui kernel e inicialização Linux próprios.

## Rollback

Restaure o pacote ou commit anterior e reconcilie o Control Center. A auditoria
não altera bancos, volumes, stacks ou serviços das aplicações; portanto não há
rollback de dados. Nunca remova volumes ou aplicações para desfazer esta
correção.
