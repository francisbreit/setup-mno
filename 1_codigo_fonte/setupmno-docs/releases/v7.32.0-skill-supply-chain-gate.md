# v7.32.0 — Skill Supply Chain Gate

- Versão planejada: 7.32.0
- Estado: `implemented`
- Maturidade: `beta`
- Atualizado em: 2026-08-24
- Responsável: Francis MNO, único mantenedor PRO MASTER
- Ambientes: repositório de construção em Debian, Ubuntu ou WSL2
- Arquiteturas: independente de x86/ARM; não executa o candidato
- Planos afetados: governança exclusiva PRO MASTER; nenhum runtime de cliente

## Resumo para leigos

A v7.32.0 cria uma alfândega para skills externas. Antes de pensar em usar uma
skill encontrada na internet, o sistema confere sua identidade, licença,
arquivos, hashes, URLs, dependências, comandos e permissões. A skill nunca é
executada durante essa conferência.

> **BETA:** o gate já bloqueia os riscos cobertos pelos testes, mas ainda será
> ampliado a partir de candidatos reais. Passar no gate não significa que a
> skill foi instalada, homologada ou liberada aos clientes.

## Problema resolvido

Popularidade, estrelas e presença em um catálogo não provam que o conteúdo
baixado é o mesmo que alguém revisou. Também não provam que uma skill não pede
sudo, Docker socket, credenciais ou comandos capazes de alterar a VPS. O gate
transforma essas perguntas em verificações repetíveis antes da revisão humana.

## Jornada do mantenedor

1. Francis recebe uma cópia isolada da skill e seu `skill-manifest.json`.
2. Abre o assistente guiado no repositório de construção.
3. O gate lê os arquivos sem executar scripts ou acessar a internet.
4. Um risco bloqueante encerra o fluxo e explica o motivo.
5. Um candidato sem bloqueios recebe um token ligado aos hashes exatos.
6. O PRO MASTER digita o token somente depois da leitura do relatório.
7. O resultado autoriza apenas a próxima revisão canônica.

## Arquitetura e permissões

- analisador determinístico em Python, usando somente a biblioteca padrão;
- assistente Bash/Whiptail com alternativa textual;
- manifesto schema 1 e inventário estrito;
- relatórios temporários atômicos com modo `0600`;
- nenhuma rede, root, sudo, Docker socket, shell de produção ou secret;
- nenhuma instalação, cópia canônica, commit, tag, release ou publicação.

## Gates implementados

- [x] origem GitHub HTTPS e commit completo de 40 caracteres;
- [x] licença por identificador SPDX suportado e arquivo de licença;
- [x] versão SemVer exata, dependências fixas e SHA-256;
- [x] inventário estrito com caminho, tamanho, modo e hash;
- [x] bloqueio de symlink, arquivo extra, binário não revisado e path inseguro;
- [x] URLs HTTPS declaradas, sem credenciais, parâmetros ou fragmentos;
- [x] comparação entre comandos encontrados no shell e comandos declarados;
- [x] bloqueio de segredo aparente, `curl|sh`, `eval`, `rm -rf`, sudo,
  Docker socket, `chmod 777` e shell dinâmico;
- [x] bloqueio de ação mutável e permissões administrativas;
- [x] token de confirmação ligado ao hash exato do candidato;
- [x] testes positivo, aprovação, pacote perigoso, adulteração e arquivo extra.

## Resultado na tela

O cabeçalho mostra `SKILL_SUPPLY_CHAIN_GATE · BETA`. A decisão será uma destas:

- `blocked`: há risco ou divergência que impede a revisão;
- `awaiting-pro-master-review`: checks automáticos passaram, mas falta Francis;
- `approved-for-canonical-review`: o conteúdo exato pode seguir para outra
  revisão; nada foi instalado.

## Segurança, limites e falhas conhecidas

- análise estática não prova ausência de comportamento malicioso;
- o token evita aprovar conteúdo alterado, mas não autentica o mantenedor;
- a licença declarada ainda exige conferência humana e jurídica quando preciso;
- esta versão aceita repositórios GitHub e uma allowlist inicial de licenças;
- o extrator de comandos é conservador e pode pedir declaração adicional;
- o gate não possui integração com Codex, Claude Code, Hermes ou OpenClaw;
- nenhum arquivo desta base é publicado automaticamente no Control Center.

## Teste no WSL2 ou VPS de construção

```bash
bash 1_codigo_fonte/setupmno-docs/tools/test-skill-supply-chain-gate.sh
```

Resultado esperado:

```text
SKILL_SUPPLY_CHAIN_TESTS_OK safe=1 approval=1 blocked=1 tamper=1 extra=1 strict=1
```

O teste usa apenas fixtures fictícias e diretórios temporários. Não o execute
em uma pasta com dados de clientes.

## Rollback

Reverter o commit da v7.32.0 remove somente o gate, suas fixtures e documentos.
Como nenhuma skill é instalada, não há stack, serviço, volume, banco, DNS ou
dado de cliente para restaurar. A v7.31.0 permanece como versão estável até uma
nova declaração explícita de Francis MNO.

## Como explicar para a comunidade

“O Setup MNO não instala uma skill só porque ela está popular. Primeiro ela
passa por uma alfândega que confere origem, licença, arquivos e permissões. Se
pedir acesso perigoso, é barrada. Mesmo quando passa, ainda depende da revisão
humana e não ganha acesso ao servidor.”
