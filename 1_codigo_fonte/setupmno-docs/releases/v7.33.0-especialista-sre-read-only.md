# v7.33.0 — Especialista SRE em modo somente leitura

- Versão planejada: 7.33.0
- Estado: `implemented`
- Maturidade: `beta`
- Atualizado em: 2026-08-24
- Responsável: Francis MNO
- Ambientes: VPS Debian/Ubuntu e WSL2 com Docker Desktop
- Arquiteturas: AMD64 e ARM64
- Planos afetados: todos

## Para iniciantes — o que isso resolve

O Assistente MNO passa a receber uma fotografia segura do servidor em vez de
listas com nomes reais. Ele pode explicar capacidade, réplicas e sinais de
falha sem obter comandos, credenciais ou poder de alteração.

## Objetivo e critérios de sucesso

- produzir snapshot sanitizado por endpoint fixo;
- separar fatos observados de hipóteses;
- devolver somente contagens de sinais de logs;
- funcionar em todos os planos com as mesmas proteções;
- bloquear resposta fora do schema ou com flags de mutação;
- não reiniciar, criar, atualizar ou excluir recursos Docker.

## Jornada do usuário

1. Abrir **Assistente MNO**.
2. Ler a faixa visível **Especialista SRE · BETA**.
3. Executar o diagnóstico seguro ou fazer uma pergunta de infraestrutura.
4. Receber fatos, hipóteses claramente identificadas, limites e próximo passo.
5. Sair sem qualquer alteração no servidor.

## Arquitetura e segurança

- agente: `GET /sre/snapshot`, token interno e Docker API limitada a leituras;
- painel: `GET /api/sre/snapshot`, sessão administrativa e sem Docker socket;
- Assistente: recebe somente snapshot validado e catálogo/conhecimento
  necessários;
- logs: conteúdo processado e descartado localmente;
- serviços: referências opacas renovadas a cada coleta;
- nenhuma API de shell, comando Docker livre ou mutação foi adicionada.

## Gates executados

- testes Go do coletor, sanitização, referências opacas e proxy autenticado;
- teste negativo para flags de mutação e log bruto;
- teste de allowlist confirmando somente métodos GET;
- teste de frontend para rótulo Beta e mensagem de não alteração;
- matriz de planos confirmando proteção universal;
- build e smoke test isolado no Docker de homologação;
- gerador, manifests, x86/ARM, SHC e catálogo aprovados;
- empacotamento oficial registrado depois do commit da implementação.

## Limitações

- snapshot pontual, sem histórico;
- no máximo 60 serviços, 40 eventos e oito serviços degradados com sinais de
  log por coleta;
- contagem de sinal não confirma causa;
- diagnóstico não substitui backup, observabilidade ou análise humana;
- classificação permanece Beta até homologação explícita.

## Rollback

Usar a release anterior remove o endpoint e a UX SRE. Como a feature não grava
estado nem altera o Docker, não há migração ou rollback de dados.

## Como testar no WSL2 e na VPS

Consulte `sre/manual/usar-diagnostico-seguro.md`. Resultado esperado: faixa
Beta, mensagem de que nenhuma alteração ocorreu, fatos separados de hipóteses,
referências opacas e ausência de dados reais do ambiente.
