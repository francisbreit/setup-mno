## 1. Para Iniciantes: O que esta versão entrega?

A versão **v7.48.22** entrega a **automação completa de liberação (Bypass) da Torre Master no Cloudflare Zero Trust**, permitindo que a Torre Master monitore perfeitamente seus nós operários em tempo real, mesmo quando o login via navegador exige autenticação multifator (MFA / 2FA).

### O Modelo Mental: A Portaria Blindada e o Crachá VIP da Torre Master
Imagine que o seu servidor é um prédio comercial com uma portaria eletrônica rigorosa (Cloudflare Access com MFA):
- **O Visitante Humano (Você no Navegador):** Chega na portaria, precisa digitar seu e-mail e o código de 6 dígitos gerado pelo celular (MFA / TOTP) para entrar. Isso impede que qualquer hacker no mundo invada o seu painel.
- **O Inspetor de Segurança (A Torre Master):** Precisa inspecionar o prédio a cada 15 segundos para conferir se os 25 serviços Docker estão saudáveis e medir uso de CPU e memória. Porém, como a Torre Master é um servidor automático e não tem dedos nem celular para digitar códigos de 6 dígitos, ela batia na porta e recebia uma resposta 403 / HTML do Cloudflare, ficando cega para o status dos containers.
- **A Solução na v7.48.22 (Regra de Bypass Automática):**  
  Em vez de obrigar você a entrar no painel da Cloudflare e criar regras manuais complexas, o Setup MNO agora faz tudo com **1 comando ou 1 clique no menu visual**:
  1. Ele conversa diretamente com a API do Cloudflare Zero Trust usando as permissões que você já concedeu.
  2. Ele adiciona uma regra especial dizendo à Cloudflare: *"Se a conexão vier do IP da Torre Master (ou for na rota `/api/fleet/*`), libere a passagem sem pedir código de 6 dígitos"*.
  3. Resultado: A sua Torre Master enxerga imediatamente todos os serviços com status **🟢 Online**, enquanto o painel web continua 100% blindado por MFA para qualquer outra pessoa na internet! E tudo isso no **plano 100% gratuito da Cloudflare**, sem gastar nem 1 centavo!

## 2. Nota Técnica para DevOps: Arquitetura e Blindagens Implementadas

### A. Automação de Políticas de Bypass via Cloudflare Access API
- **Endpoint Utilizado:** `POST /accounts/$ACCOUNT_ID/access/apps/$app_id/policies`
- **Reaproveitamento de Permissões (Zero Permissões Extras):**
  A automação aproveita o escopo de token preexistente `Conta > Access: Apps and Policies > Editar`, dispensando a criação de novas chaves de API ou intervenção manual no Cloudflare Dashboard.
- **Dois Modos de Bypass Suportados:**
  1. **Bypass por IP Público da Torre Master (Recomendado para VPS):**
     Cria uma política de precedência 1 (`decision: "bypass"`) apontando exclusivamente para o IP da Torre Master (`include: [{ip: {ip: "$IP/32"}}]`).
  2. **Bypass de Rota de Telemetria (Recomendado para WSL2 / IPs Dinâmicos):**
     Cria uma sub-aplicação Access isolada no caminho `$url_control/api/fleet/*` com decisão `bypass` para requisições de handshake e métricas autenticadas pelo segredo de frota (`Authorization: Bearer <fleet-token>`).

### B. Integração Visual e CLI no Setup MNO
- **Menu Visual Whiptail:**
  Em `CONFIGURAR MFA CONTROL CENTER`, foi adicionada a opção `BYPASS` permitindo adicionar e remover regras de Bypass de forma assistida.
- **Flags de Linha de Comando (CLI):**
  - `--add-access-bypass <IP>`: Registra e aplica imediatamente a regra de bypass na Cloudflare para o IP da Torre Master.
  - `--remove-access-bypass [IP]`: Remove regras de bypass gerenciadas pelo Setup MNO.
  - `--add-telemetry-bypass`: Cria aplicação específica de bypass na rota `/api/fleet/*`.

### C. Rigorosa Proteção de Tamanho SHC
- A lógica de API da Cloudflare foi encapsulada em `1_codigo_fonte/setupmno-control/cloudflare-mfa.sh`, mantido no tarball do runtime (`control-source.tar.gz`).
- O script montador `installer-template.sh` foi otimizado para **122.524 bytes** (abaixo do teto rígido de 122.880 bytes), garantindo compilação SHC infalível e livre de truncamentos em arquiteturas x86_64 e aarch64.
