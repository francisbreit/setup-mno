# v7.33.1 — APT não interativo no Docker Swarm

- Versão: 7.33.1
- Estado: `implemented`
- Maturidade: `stable`
- Atualizado em: 2026-08-24
- Responsável: Francis MNO
- Ambientes: Debian e Ubuntu em VPS; Ubuntu no WSL2
- Arquiteturas: x86-64 e ARM64
- Planos afetados: todos

## Para iniciantes

O instalador das ferramentas essenciais ainda continha um comando que tentava
atualizar todos os pacotes da VPS. No Ubuntu 24.04, esse comando podia abrir a
tela `Configuring keyboard-configuration`. Como a tela de progresso do Setup
MNO ficava na frente, a pergunta não aparecia e a instalação parecia travada em
17%.

A v7.33.1 corrige exatamente esse ponto. O Setup instala somente os pacotes de
que precisa, responde de modo automático às perguntas conhecidas e para com uma
mensagem clara se o sistema operacional devolver um erro real.

## Modelo mental

Imagine que o Setup precisa instalar uma fechadura. Antes, ele aproveitava para
reformar a casa inteira e podia parar esperando uma escolha sobre o teclado.
Agora ele compra apenas a fechadura e mostra um relógio enquanto o serviço está
em andamento.

## O que mudou

- removido o `apt upgrade` completo dos dois `dockerswarm.sh`;
- x86-64 e ARM64 usam a mesma política não interativa;
- `Debconf`, mecanismo usado por pacotes para fazer perguntas, recebe modo não
  interativo e prioridade crítica;
- `needrestart`, ferramenta que pergunta sobre reinício de serviços, usa modo
  automático;
- arquivos de configuração existentes são preservados;
- o Setup aguarda por até 300 segundos se outro APT legítimo estiver usando o
  gerenciador de pacotes;
- o coração de atividade mostra mensagem, animação e tempo decorrido sem
  inventar avanço no percentual;
- falhas ficam registradas em `/tmp/setupmno-dockerswarm-apt.log` e interrompem
  a instalação.

## O que permaneceu igual

- Docker Engine, Docker Swarm, Traefik, Portainer, PostgreSQL, Redis e PgBouncer
  continuam sendo preparados pelo mesmo fluxo;
- a detecção de Debian, Ubuntu, WSL2, x86-64 e ARM64 não mudou;
- a correção não altera aplicações, volumes, bancos, DNS ou Cloudflare Tunnel;
- a manutenção completa e as atualizações de segurança da VPS continuam sendo
  uma rotina separada do administrador.

## Nota técnica para DevOps

O helper fixo executa `apt-get` com:

```text
DEBIAN_FRONTEND=noninteractive
DEBCONF_NONINTERACTIVE_SEEN=true
DEBIAN_PRIORITY=critical
NEEDRESTART_MODE=a
APT_LISTCHANGES_FRONTEND=none
UCF_FORCE_CONFFOLD=1
DPkg::Lock::Timeout=300
--force-confdef
--force-confold
```

As listas de pacotes são escritas no código e não recebem texto livre do
usuário. Há um `apt-get update` para os repositórios do sistema e outro após a
inclusão do repositório oficial do Docker. Não há `apt-get upgrade` no fluxo.

O heartbeat conserva o percentual da etapa porque tempo decorrido não prova
progresso real do APT. Ele serve para mostrar que o processo ainda está vivo,
sem transformar uma estimativa em fato.

## Como testar no WSL2

Pré-requisitos: Ubuntu no WSL2, Docker Desktop integrado e uma instalação de
homologação que possa ser reinstalada.

1. No repositório de construção, execute:

   ```bash
   bash 1_codigo_fonte/setupmno-control/apt-noninteractive_test.sh
   ```

2. Resultado esperado:

   ```text
   APT não interativo no bootstrap e Docker Swarm, sem upgrade obrigatório, com heartbeat e falha bloqueante aprovado.
   ```

3. Em uma instalação limpa, acompanhe a etapa das ferramentas essenciais.
4. A mensagem deve mudar entre índice, dependências, repositório do Docker e
   Docker Engine. Durante esperas, o tempo deve continuar aumentando.
5. Não deve aparecer nenhuma tela de configuração de teclado.

Sinal de falha: percentual parado sem animação e sem tempo, diálogo Debconf,
continuação após erro do APT ou ausência do log indicado na tela.

## Como testar em VPS Ubuntu 24.04 ARM64

Use uma VPS descartável ou um snapshot que possa ser restaurado.

1. Execute uma instalação limpa da candidata v7.33.1.
2. Confirme que a tela de 17% mostra atividade e tempo decorrido.
3. Confirme que não aparece `Configuring keyboard-configuration`.
4. Ao finalizar, confira:

   ```bash
   docker info --format '{{.Swarm.LocalNodeState}}'
   docker service ls
   ```

5. O primeiro comando deve retornar `active`. Os serviços essenciais devem
   aparecer e alcançar as réplicas esperadas.

Para diagnosticar uma espera sem revelar o conteúdo protegido pelo SHC:

```bash
ps -eo pid,ppid,stat,etime,comm | grep -E '[a]pt|[d]pkg|[d]ebconf|[w]hiptail'
tail -n 80 /tmp/setupmno-dockerswarm-apt.log
```

Não use as colunas `cmd` ou `args` para inspecionar o processo protegido. O SHC
entrega o script ao Bash como argumento e essas colunas podem imprimir grande
parte do código na tela.

Repita também em uma VPS x86-64 e em Debian 13 antes de promover a candidata
como versão estável.

## Erros comuns

- **Outro APT já está trabalhando:** aguarde a atualização automática da VPS;
  o Setup espera até 300 segundos e não apaga locks manualmente.
- **Instalação antiga já está presa:** não inicie outra em paralelo. Conclua ou
  interrompa com segurança o diálogo antigo e repare o `dpkg` antes de tentar
  novamente.
- **Repositório do Docker indisponível:** confira conexão e o log dedicado; o
  Setup deve parar em vez de seguir com ambiente parcial.
- **Hostname diz Debian, mas o sistema é Ubuntu:** o nome do servidor não define
  a distribuição. O Setup consulta `/etc/os-release`.

## Riscos, limites e proteções

- modo não interativo usa respostas padrão ou previamente conhecidas;
- o Setup não passa a atualizar todos os pacotes de segurança da VPS;
- o log pode conter mensagens e nomes de pacotes, mas não deve conter senhas ou
  tokens;
- o timeout protege contra espera infinita pelo lock, mas não mata outro APT;
- a correção é bloqueante: uma dependência obrigatória que falhar impede a
  continuação em estado incompleto.

## Rollback

Não há migração de banco nem mudança de volume. Para voltar ao código anterior,
reverta o commit da v7.33.1 e gere novamente os pacotes. Restaurar o antigo
`apt upgrade` escondido não é recomendado. Em uma VPS de teste parcialmente
configurada, prefira restaurar o snapshot criado antes da homologação.

## Como explicar para a comunidade

“O Setup MNO não tenta mais atualizar a VPS inteira enquanto instala o Docker
Swarm. Ele instala somente o necessário, não deixa perguntas escondidas e
mostra há quanto tempo a etapa está trabalhando. Se houver um erro verdadeiro,
ele para e indica o log em vez de continuar com metade da estrutura pronta.”
