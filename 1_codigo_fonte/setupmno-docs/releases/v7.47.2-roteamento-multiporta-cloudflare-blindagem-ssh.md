## Para iniciantes

A versão **v7.47.2** resolve três desafios práticos observados durante os testes de migração e clone de aplicações entre servidores com o **MNO Fleet Hub**:

1. **MinIO e Aplicações com Múltiplas Portas Funcionando de Primeira (Fim do Erro 502 Bad Gateway):**
   - Antes, ao clonar ou migrar uma aplicação como o MinIO ou o Typebot para outro servidor, o Cloudflare Tunnel às vezes direcionava todas as URLs para a porta padrão 80. Isso fazia o MinIO dar erro 502 (Bad Gateway), porque o painel administrativo do MinIO responde na porta **9001** e a API S3 responde na porta **9000**.
   - Agora, o Setup MNO é inteligente: ele detecta exatamente qual serviço responde em qual porta (ex: Console do MinIO na 9001, API na 9000; Typebot Builder na 3000, Typebot Viewer na 3000) e configura o túnel Cloudflare do destino perfeitamente na hora da virada de chave!

2. **Fim da Tela Preta e Travamento Visual Entre Menus:**
   - Durante a seleção da aplicação para migrar, o terminal podia ficar com a tela preta por alguns segundos enquanto o sistema analisava os arquivos e conexões remotas, dando a impressão de travamento.
   - Agora, o sistema exibe imediatamente uma caixa informativa visual animada (`🔍 Analisando dependências da aplicação...`) para que você sempre saiba o que está acontecendo sem sustos.

3. **Blindagem Contra Avisos de SSH em Servidores Recriados:**
   - Quando um servidor VPS de teste é destruído e recriado do zero com o mesmo IP, o Linux costumava bloquear a conexão com alertas gigantescos de chave alterada (`REMOTE HOST IDENTIFICATION HAS CHANGED`).
   - Agora, o Fleet Clone limpa automaticamente as chaves antigas e utiliza isolamento seguro de chaves temporárias (`UserKnownHostsFile=/dev/null` e expurgo atômico com `ssh-keygen -R`), garantindo conexões suaves e sem bloqueios manuais.

## Nota técnica para DevOps: O que mudou no código

- **Roteamento Multi-Porta Dinâmico no Cloudflare Tunnel (`switch_cloudflare_dns_and_ingress`):**
  - Implementação da função auxiliar `resolve_host_service_port` que analisa o YAML da stack identificada ou aplica regras canônicas de portas para serviços conhecidos:
    - MinIO: mapeamento de subdomínios `admins3*` para `<service>:9001` e `s3*` para `<service>:9000`.
    - Typebot: mapeamento de subdomínios do Builder (`adminchat*`) para `builder:3000` e do Viewer (`chat*`) para `viewer:3000`.
    - Chatwoot, n8n, Evolution API, WordPress e demais aplicações: mapeamento estrito para os respectivos microserviços e portas declaradas.
  - Eliminação do fallback estático para a porta 80 que provocava `502 Bad Gateway` nas stacks multi-container.
- **Blindagem Global OpenSSH do MNO Fleet Hub:**
  - Injeção padronizada de `-o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o LogLevel=ERROR -o BatchMode=yes` em todas as invocações remotas (`ssh` e `timeout ssh`).
  - Chamada preventiva de `ssh-keygen -R "$_r_host"` na rotina `ensure_fleet_node_ssh_access`, impedindo falsos positivos de man-in-the-middle causados por rotação de instâncias efêmeras na frota.
- **UX Reativa e Feedback Sem Bloqueio:**
  - Injeção de `whiptail --infobox "🔍 Analisando dependências..."` pré-resolução de manifests remotos, evitando a dessincronização visual de TTY.
- **Correção da Trava de Segurança no Desligamento da Origem (`stop_origin`):**
  - Ajuste na verificação de manifestos para permitir o encerramento gracioso na origem de aplicações sem volumes persistentes mapeados (aplicações puramente stateless).

## Segurança, política de rollback e baseline estável

### Versão Estável de Referência
- A versão **v7.45.0** permanece como a versão estável homologada anterior de referência.
- A versão **v7.47.2** consolida as melhorias e correções de roteamento, resiliência SSH e UX do Fleet Clone em estado `beta`.

### Procedimento de Rollback
Caso necessário reverter qualquer modificação:
1. As configurações anteriores podem ser restauradas reinstalando os pacotes da pasta `3_distribuicao/backup/`.
2. Para instâncias já ativas, o comando `docker stack deploy -c <stack>.yaml <stack_name>` aplica alterações sem interrupção dos volumes persistentes.
