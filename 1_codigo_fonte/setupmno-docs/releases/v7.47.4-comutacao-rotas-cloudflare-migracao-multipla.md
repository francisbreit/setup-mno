## Para iniciantes

A versão **v7.47.4** resolve o problema onde o **MinIO** e o **Typebot** ficavam inacessíveis no navegador (Erro 502 Bad Gateway) após uma **migração de volta** (da Torre WSL2 para o servidor VPS):

### O que estava acontecendo?
1. Você instalou o combo **Typebot + MinIO** na VPS (Worker) e migrou para a Torre (WSL2). Tudo funcionou.
2. Depois, você decidiu migrar de volta da Torre (WSL2) para a VPS (Worker).
3. A migração parecia terminar sem erros na tela, mas ao abrir o Typebot ou o MinIO no navegador, a página dava **Erro 502 Bad Gateway**.
4. **Por que isso acontecia?**
   - Para que o seu site abra pelo Cloudflare sem abrir portas no servidor, o Setup MNO precisa avisar a Cloudflare para qual servidor o endereço da internet deve apontar (comutação de rotas DNS e Túnel).
   - Quando o comando de atualização era enviado da Torre para a VPS via conexão segura (SSH), os dados dos domínios usavam o caractere de barra vertical (`|`) para separar o domínio da porta (exemplo: `admins3clone1...|minio3cc8d89|9001`).
   - No terminal Linux remoto, a barra vertical (`|`) tem um significado especial: ela é interpretada como um comando de encadeamento ("pipeline"). O servidor tentou rodar `9001` e `minio3cc8d89` como programas inexistentes (`command not found`) e o comando que atualizava o DNS falhou silenciosamente!
   - Como o DNS não foi atualizado, a Cloudflare continuou mandando os visitantes para a Torre WSL2. Mas como você pediu para desligar na origem (`stop_origin`), as aplicações na Torre já estavam desligadas, resultando no Erro 502!
   - Além disso, o backup do banco de dados PostgreSQL tentava descompactar os dados duas vezes seguidas (`gzip: stdin: not in gzip format`), e o comando de criação do banco dava erro se o banco já existisse de uma migração anterior.

### Como foi resolvido na v7.47.4?
1. **Transporte Seguro em Base64 (Fim da colisão com o terminal):** Toda a lista de domínios, serviços e portas agora é empacotada em formato Base64 (um texto codificado limpo, sem caracteres especiais como `|`, espaços ou aspas) antes de viajar pela rede. O servidor remoto recebe o pacote intacto e atualiza os endereços DNS na Cloudflare com 100% de sucesso.
2. **Atualização Atômica de DNS (PUT):** Em vez de apagar e recriar os registros DNS, o Setup MNO agora atualiza os registros existentes instantaneamente (via requisição atômica `PUT`), eliminando qualquer momento de instabilidade.
3. **Migrações Repetidas Infinitas (Idempotência Total):** O sistema agora aceita migrar e voltar entre servidores quantas vezes você quiser. Se o banco de dados já existir de uma rodada anterior, ele não trava nem gera mensagens assustadoras; ele limpa e restaura os dados atualizados com perfeição.

## Nota técnica para DevOps: O que mudou no código

- **Blindagem de Transporte de Mapeamentos Multi-Domínio (`switch_cloudflare_dns_and_ingress`):**
  - Eliminação da passagem de argumentos desprotegidos contendo pipes (`|`) via linha de comando SSH (`ssh ... bash -s "${mappings[@]}"`).
  - Serialização dos mapeamentos `host|service|port` via codificação Base64 (`mappings_b64=$(printf '%s\n' "${mappings[@]}" | base64 -w 0)`).
  - Injeção controlada através de variável de ambiente `MAPPINGS_B64` e decodificação atômica via `base64 -d` em ambos os contextos (local e SSH remoto), eliminando a interpretação indevida de pipes pelo shell remoto (`9001: command not found`).
- **Comutação Atômica de Registros DNS CNAME Cloudflare:**
  - Consulta prévia por tipo `CNAME` (`name=${h}&type=CNAME`).
  - Execução de `PUT /zones/:zone_id/dns_records/:record_id` com payload canônico `{"type":"CNAME","name":"${h}","content":"${TUNNEL_ID}.cfargotunnel.com","ttl":1,"proxied":true}`, preservando estabilidade de propagação e prevenindo janelas de ausência de registros (zero downtime).
  - Fallback limpo com expurgo prévio de registros legados conflitantes e invocação de `POST /zones/:zone_id/dns_records` caso o registro ainda não exista.
- **Idempotência e Correção de Stream no Restore PostgreSQL (`fleet-clone.sh`):**
  - Remoção da descompressão redundante (`gunzip -c | docker exec ...`) no destino remoto sobre stream já descomprimido pelo remetente, eliminando o erro `gzip: stdin: not in gzip format`.
  - Invocação idempotente de criação de banco de dados via query de verificação (`SELECT 1 FROM pg_database WHERE datname = '$pg_dbname'` com operador `|| CREATE DATABASE`), prevenindo falhas bloqueantes de colisão em migrações reversas sucessivas.
- **Auditoria Conclusiva de Ambientes:**
  - Revalidação e testes bem-sucedidos em round-trip entre WSL2 AMD64 e VPS Hetzner Debian 13 (`91.99.117.159`), com verificação de HTTP 200 OK nos endpoints públicos de Typebot Builder, Typebot Viewer, MinIO Console e MinIO S3 API.

## Segurança, política de rollback e baseline estável

### Versão Estável de Referência
- A versão **v7.45.0** permanece como a versão estável homologada anterior de referência.
- A versão **v7.47.4** consolida a estabilização de comutação de rotas e idempotência de migrações reversas no MNO Fleet Hub em estado `beta`.

### Procedimento de Rollback
Caso necessário reverter qualquer modificação:
1. As configurações anteriores podem ser restauradas reinstalando os pacotes da pasta `3_distribuicao/backup/`.
2. Para instâncias já ativas, o comando `docker stack deploy -c <stack>.yaml <stack_name>` aplica alterações sem interrupção dos volumes persistentes.
