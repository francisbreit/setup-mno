## Para iniciantes

A versão **v7.48.0** conclui as **Fases 3 e 4 do MNO Fleet Hub**, trazendo o poder dos **Backups e Restaurações Portáteis Universais** para aplicações individuais e **Combos Integrados completos**:

### O que essa versão faz?

1. **Reconhecimento Automático de Combos nos Backups:**
   - Ao pedir para gerar um Backup Portátil (`.tar.gz`) de qualquer ferramenta de um combo (como Chatwoot, Typebot, Mautic, EvoAI ou Dify), o Setup MNO reconhece instantaneamente todas as ferramentas irmãs conectadas ao mesmo grupo.
   - O sistema abre um diálogo claro e pergunta:
     - **Opção 1: BACKUP DO COMBO COMPLETO** (empacota todas as ferramentas do combo em um único arquivo `.tar.gz` consistente).
     - **Opção 2: BACKUP APENAS DA FERRAMENTA ESCOLHIDA** (gera o backup isolado somente da aplicação selecionada).

2. **Captura Completa de Dados e Volumes Persistentes:**
   - Não salvamos apenas o arquivo de configuração YAML: o sistema faz o snapshot de **todos os volumes Docker persistentes** de cada stack (como mídias locais, uploads, configurações e caches) em arquivos compactados individuais `volumes/vol_<nome>.tar.gz`.
   - Se a aplicação usar bancos de dados relacionais (**PostgreSQL**, **MySQL 8.0** ou **MySQL 8.4**) ou NoSQL (**MongoDB**), o dump lógico compactado e consistente é gerado e armazenado na pasta `dumps/`.
   - Um manifesto enriquecido (`manifest.json` schemaVersion 2) registra arquitetura de origem, domínios, portas e dependências.

3. **Restauração Universal Automatizada em 1 Clique:**
   - No menu do Fleet Clone, agora você tem a opção: **`5) Restaurar Backup Portátil em um Servidor (Local ou Remoto)`**.
   - Você escolhe o arquivo `.tar.gz` (o sistema lista automaticamente os backups salvos em `/root/backup_fleet/`).
   - Você escolhe onde quer restaurar (no servidor atual ou em qualquer servidor remoto da sua frota).
   - O sistema valida memória RAM e espaço em disco, provisiona automaticamente as dependências necessárias (PostgreSQL, MySQL, MinIO S3 ou RabbitMQ), recria os volumes Docker, restaura os bancos de dados e coloca todas as stacks para rodar no Docker Swarm via Portainer.

4. **Decisão Inteligente sobre Domínios e Cloudflare DNS:**
   - O backup portátil nunca mexe nos seus domínios ou na internet quando é criado.
   - Na hora de **restaurar**, o Setup MNO pergunta exatamente o seu objetivo:
     - **Recuperação de Desastre / Produção (Disaster Recovery):** O sistema comuta imediatamente as rotas do Cloudflare Tunnel e atualiza o DNS para o servidor onde você restaurou o backup.
     - **Cópia de Teste / Homologação (Clone):** O sistema deixa o DNS original intacto na internet e ensina como testar a cópia de forma segura.

5. **Notificações em Tempo Real (MNO Sentinel):**
   - Ao concluir uma migração, backup ou restauração, o sistema pode disparar um relatório executivo com detalhes de volumes, nós e domínios diretamente para o seu Telegram ou Webhook no n8n.

## Nota técnica para DevOps: O que mudou na arquitetura

- **Agrupador Heurístico e Gerador de Pacote Portátil (`action_backup_app`):**
  - Detecção topológica de instâncias conectadas por sufixo e variáveis de ambiente via `detect_app_combo_context`.
  - Estruturação do bundle `.tar.gz` universal:
    - `manifest.json` (schemaVersion 2) com metadados de stacks, nós, domínios, portas e volumes.
    - `stacks/<app>.yaml` para cada stack pertencente ao combo ou aplicação isolada.
    - `volumes/vol_<app_volume>.tar.gz` para persistência integral de dados não-banco.
    - `dumps/<app>_logical_dump.sql.gz` ou `dumps/<app>_mongo_dump.tar.gz` com dumps atômicos.
- **Motor de Restauração Automatizada (`action_restore_backup`):**
  - Descoberta e seleção de backups em `/root/backup_fleet/` ou paths arbitrários.
  - Validação de integridade do manifesto e compatibilidade cruzada com backups schemaVersion 1 legados.
  - Seleção de destino (nó local ou nós remotos gerenciados via SSH seguro).
  - Preflight checks de memória livre, espaço em disco e paridade arquitetural (x86-64 / ARM64).
  - Provisionamento ordenado de dependências (`ensure_mysql_ready`, `ensure_mysql84_ready`, `ensure_minio_ready`, `ensure_rabbitmq_ready`).
  - Restauração atômica de volumes Docker via container utilitário efêmero `alpine`.
  - Restauração de bancos relacionais e NoSQL idempotente com criação condicional.
  - Deploy no Swarm via API Portainer com `endpoint_id` resolvido dinamicamente.
  - Gate interativo de comutação Cloudflare Tunnel / DNS CNAME com fallback limpo.
- **Suporte Expandido de Motores de Banco de Dados:**
  - Adição de suporte a MongoDB (`mongodump` e `mongorestore` com compressão gzip em streaming) para aplicações NoSQL como RocketChat e LibreChat.
  - Integração no `fleet_transfer.go` do Go Control Center e unit tests atualizados.
- **Sentinel Dispatcher Bash (`dispatch_sentinel_notification_bash`):**
  - Envio de notificações de governança e auditoria via Telegram Bot API (Markdown) e Webhooks n8n (`/webhook/mno-sentinel`).
- **Paridade Estrita x86-64 e ARM64:**
  - Totalmente espelhado entre `1_codigo_fonte/x86/SetupLowCodeMno/fleet-clone.sh` e `1_codigo_fonte/arm/SetupLowCodeMno/fleet-clone.sh`.

## Segurança, política de rollback e baseline estável

### Versão Estável de Referência Fixada
- A versão **v7.47.4** permanece como a **versão estável de referência fixada** até homologação formal em produção e declaração explícita de Francis MNO.
- A versão **v7.48.0** opera com maturidade **BETA**, habilitada para validação e testes controlados de restauração e backups em massa.

### Procedimento de Rollback
Caso necessário retornar à versão de referência anterior:
1. Restaurar os pacotes de `3_distribuicao/backup/` ou reverter para a tag Git `v7.47.4`.
2. Os volumes originais antes da restauração ou migração são preservados com sufixo `_bak_` e os arquivos de origem nunca são apagados na criação de backups.
