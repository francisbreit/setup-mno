## Para iniciantes

A versão **v7.47.1** resolve um problema crítico e silencioso que impedia a criação de buckets e a vinculação de chaves S3 (`S3_ACCESS_KEY` e `S3_SECRET_KEY`) nos combos que usam o **MinIO** (como **Typebot com MinIO**, **Chatwoot com MinIO**, **EvoAI** e **Dify**).

### O que aconteceu nos bastidores?
O projeto oficial do MinIO desativou os links antigos de download direto na internet (`dl.min.io`) retornando um erro chamado `410 Gone` (recurso removido). 
Quando o Setup MNO era executado em um servidor novo, o comando tentava baixar a ferramenta auxiliar `mc` (MinIO Client). Como o link oficial morreu, o servidor criava um arquivo vazio de **0 bytes**. O sistema achava que a ferramenta estava instalada, mas ao tentar criar o bucket e as chaves de acesso, nada acontecia! O Typebot subia com as variáveis `S3_ACCESS_KEY=` e `S3_SECRET_KEY=` em branco, e o bucket não era criado no MinIO.

### A solução genial do Setup MNO v7.47.1
1. **Fim da Dependência da Internet para o MinIO Client:** Descobrimos que o container do próprio MinIO já vem de fábrica com o `mc` embutido dentro dele! Agora, o Setup MNO executa os comandos diretamente dentro do container ou extrai o executável oficial para o servidor em menos de 2 segundos, sem depender de nenhum site externo que possa sair do ar.
2. **Conexão Direta e Instantânea (Localhost:9000):** Em vez de esperar pelo DNS da internet ou rotas externas para configurar o MinIO, o Setup MNO cria o bucket e as chaves de acesso diretamente na porta interna do container. É instantâneo, seguro e à prova de lentidão.
3. **Cinto de Segurança (Fallback de Credenciais):** Se a criação de uma chave de serviço falhar por qualquer motivo, o instalador automaticamente injeta as credenciais root seguras do MinIO. Dessa forma, as variáveis do Typebot e do Chatwoot **NUNCA mais ficam vazias**!

## Nota técnica para DevOps: O que mudou no código

- **Descomissionamento do Endpoint `dl.min.io`:**
  - Substituição da chamada legada `wget https://dl.min.io/client/mc/release/...` em todos os instaladores (`typebot_minio.sh`, `chatwootorig_desbloq__evo2_rabbitmq_minio.sh`, `chatwootn_evo2_rabbitmq_minio.sh`, `chatwooto_evo2_rabbitmq_minio.sh`, `evoai_evo2_minio.sh` e `dify.sh`) em ambas as arquiteturas x86-64 e ARM64.
- **Estratégia Container-First para o MinIO Client:**
  - Validação estrita de binário existente (`command -v mc && [ -s "$(command -v mc)" ] && mc --version`).
  - Extração atômica in-host via container ativo (`docker cp $CONTAINER_ID:/usr/bin/mc /usr/local/bin/mc`) ou imagem oficial multi-arch (`quay.io/minio/mc:latest`).
- **Loopback Interno de Comunicação S3:**
  - Execução de comandos administrativos (`mc alias set`, `mc mb`, `mc anonymous set public` e `mc admin user svcacct add`) via `docker exec $CONTAINER_ID` apontando para `http://localhost:9000`, eliminando qualquer dependência de propagação DNS ou tunelamento Cloudflare durante o provisionamento.
- **Reconciliação e Fallback Inviolável de Credenciais S3:**
  - Extração de chaves via `jq -r '.accessKey // empty'` e fallback para parsing de texto simples.
  - Fallback mandatório: caso `access_key` ou `secret_key` retornem vazios, a função herda automaticamente `MINIO_ROOT_USER` e `MINIO_ROOT_PASSWORD`, impedindo variáveis vazias na stack da aplicação.
- **Correção de Typo no Polling de Containers:**
  - Correção de `elaapsed_time` para `elapsed_time` na rotina de espera ativa de containers.

## Segurança, política de rollback e baseline estável

### Versão Estável de Referência
- A versão **v7.45.0** permanece como a versão estável homologada anterior de referência.
- A versão **v7.47.1** consolida a correção universal do subsistema MinIO para todos os combos em estado `beta`.

### Procedimento de Rollback
Caso necessário reverter qualquer modificação:
1. As configurações anteriores podem ser restauradas reinstalando os pacotes da pasta `3_distribuicao/backup/`.
2. Para instâncias já ativas, o comando `docker stack deploy -c <stack>.yaml <stack_name>` aplica alterações sem interrupção dos volumes persistentes.
