3. **Correção de Reconciliação do Control Center (Prevenção de Falha em Upgrades):**
   - **Diagnóstico:** Ao aumentar a base para 159 setups, o dataset determinístico de testes de avaliação (Evals) subiu de 878 para 883 casos. A constante `evalExpectedCases` em `evals.go` ainda estava fixada em 878, fazendo o teste `knowledgecheck` rejeitar a imagem Docker com o erro `pacote de conhecimento inválido: contagens do manifesto inválidas`.
   - **Resolução:** Sincronizada a constante `evalExpectedCases = 883` em `evals.go`, `evals_test.go` (879 retrieval + 4 routing), `main_test.go`, `generate-installers.sh`, `installer-template.sh` e gatilhos de runtime `start_full.sh` / `start_arm_full.sh`.

## 2. Checklist Obrigatório de 6 Pontos para Novos Setups / Evals

Sempre que a contagem de casos de teste mudar no `dataset.json`, sincronizar os 6 pontos:

1. `1_codigo_fonte/setupmno-knowledge/tools/eval_factory.py` -> `EXPECTED_CASES = N`
2. `1_codigo_fonte/setupmno-knowledge/evals/dataset.json` -> Gerado via `python3 eval_factory.py`
3. `1_codigo_fonte/setupmno-control/evals.go` -> `evalExpectedCases = N`
4. `1_codigo_fonte/setupmno-control/evals_test.go` -> `report.RetrievalCases != N - 4` e `main_test.go` -> `EvalCaseEntries != N`
5. `1_codigo_fonte/x86/start_full.sh` e `arm/start_arm_full.sh` -> `EXPECTED_EVAL_CASE_ENTRIES="N"` e `EXPECTED_CATALOG_ENTRIES="M"`
6. `1_codigo_fonte/setupmno-control/installer-template.sh` e `generate-installers.sh` -> `eval_case_entries = N`
