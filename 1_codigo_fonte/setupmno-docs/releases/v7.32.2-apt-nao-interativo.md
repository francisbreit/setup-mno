# v7.32.2 — APT não interativo e bootstrap determinístico

- Versão: 7.32.2
- Estado: `implemented`
- Maturidade: `stable`
- Atualizado em: 2026-08-24
- Responsável: Francis MNO
- Ambientes: Ubuntu e Debian em VPS; Ubuntu no WSL2
- Arquiteturas: x86-64 e ARM64
- Planos afetados: todos

## Para iniciantes

O instalador ficava aparentemente travado porque o Ubuntu podia abrir uma tela
de configuração do teclado durante `apt-get upgrade`. O spinner continuava
visível, mas a pergunta do sistema ficava escondida pela saída silenciosa.

A opção `-y` do APT aceita confirmações simples, mas não responde às telas do
Debconf, sistema usado pelos pacotes para fazer perguntas. A v7.32.2 impede
essas telas durante a automação e não atualiza todos os pacotes da VPS como
efeito colateral da instalação do Setup MNO.

## Modelo mental

Antes, para instalar uma ferramenta, o Setup MNO tentava reformar a casa
inteira. Agora ele confere a lista da loja e compra somente as peças necessárias
para trabalhar. A atualização completa do sistema continua possível, mas é uma
tarefa de manutenção separada.

## O que mudou

- removido todo `apt-get upgrade` obrigatório dos dois bootstraps e dos
  gatilhos x86/ARM;
- removidas atualizações repetidas da lista de pacotes dentro da mesma etapa;
- dependências instaladas com `DEBIAN_FRONTEND=noninteractive`;
- respostas já existentes marcadas como conhecidas pelo Debconf;
- `needrestart` configurado para não abrir perguntas durante a automação;
- espera de até 300 segundos quando outro processo legítimo estiver usando o
  APT;
- arquivos de configuração existentes preservados com `--force-confold`;
- o executor deixou de usar `eval` e agora recebe comando e argumentos de forma
  estruturada;
- saída técnica gravada em log e erro devolvido ao instalador.

## O que permaneceu igual

- o Setup MNO ainda atualiza o índice de pacotes antes da instalação;
- dependências obrigatórias continuam sendo instaladas;
- correção do repositório Azlux legado no Debian 13 foi preservada;
- detecção de arquitetura, plano, Docker Desktop e Docker Swarm não mudou;
- nenhuma aplicação, stack, volume, banco, DNS ou Tunnel é alterado por esta
  correção.

## Arquitetura e segurança

O helper executa o equivalente a:

```bash
env \
  DEBIAN_FRONTEND=noninteractive \
  DEBCONF_NONINTERACTIVE_SEEN=true \
  NEEDRESTART_MODE=a \
  apt-get -y \
  -o DPkg::Lock::Timeout=300 \
  -o Dpkg::Options::=--force-confold \
  install pacote-necessario
```

O nome do pacote não é recebido de entrada livre do usuário. Os pacotes fazem
parte de listas fixas e versionadas no instalador. O `eval` foi removido para
evitar que texto seja reinterpretado como código pelo shell.

## Logs e falhas

- bootstrap público: `/tmp/setup-mno-bootstrap-apt.log`;
- gatilho protegido x86/ARM: `/tmp/setupmno-start-apt.log`;
- falha na atualização ou instalação encerra a etapa;
- as últimas linhas do log são apresentadas no diagnóstico;
- o Setup não mostra sucesso quando o APT retornou erro.

O timeout de 300 segundos espera somente pelo lock do gerenciador de pacotes.
Ele não mata outro APT nem remove arquivos de lock manualmente.

## Como recuperar uma instalação anteriormente interrompida

Não inicie dois processos APT ao mesmo tempo. Primeiro confira:

```bash
ps -eo pid,stat,etime,cmd | grep -E '[a]pt-get|[d]pkg|keyboard-configuration'
```

Depois que o processo anterior terminar ou for encerrado com segurança, conclua
a configuração pendente:

```bash
dpkg --configure -a
apt-get -f install
```

Esse procedimento de recuperação pode abrir perguntas legítimas e deve ser
acompanhado pelo administrador. Em seguida, execute o Setup MNO novamente.

## Como testar no WSL2

1. Abra o Docker Desktop e confirme a integração com Ubuntu.
2. Execute a instalação da candidata v7.32.2 em um ambiente de teste.
3. Confirme que não aparece a tela `Configuring keyboard-configuration`.
4. Confira que a instalação mostra sucesso nas dependências.
5. Em caso de falha, confirme a existência do log indicado na tela.

Teste determinístico do código-fonte:

```bash
bash 1_codigo_fonte/setupmno-control/apt-noninteractive_test.sh
```

Resultado esperado:

```text
APT não interativo, sem upgrade obrigatório, sem eval e com falha bloqueante aprovado.
```

## Como testar em VPS Ubuntu 24.04 e Debian 13

Use uma VPS descartável ou snapshot de homologação. Execute instalação limpa e
reinstalação. O resultado esperado é:

- nenhuma tela de configuração de teclado;
- somente um `apt-get update` por etapa;
- nenhuma execução de `apt-get upgrade` pelo Setup MNO;
- dependências instaladas e fluxo prosseguindo normalmente;
- Debian 13 sem retorno do repositório Azlux legado;
- falha real do APT interrompendo a instalação com caminho do log.

Sinais de falha: spinner infinito, diálogo Debconf, dois processos APT do Setup
simultâneos, mensagem `✗` seguida pela continuação do instalador ou arquivo de
configuração substituído sem confirmação.

## Limitações

- o Setup MNO não passa a manter todos os pacotes da VPS atualizados;
- atualizações de segurança do sistema operacional continuam sendo uma rotina
  separada do administrador;
- uma configuração `dpkg` já quebrada deve ser reparada antes de reinstalar;
- modo não interativo usa respostas existentes ou padrões do pacote. Quando uma
  resposta específica for obrigatória, ela deverá ser adicionada de forma
  determinística e documentada.

## Rollback

Reverter os commits da v7.32.2 restaura o comportamento anterior do bootstrap,
mas não é recomendado restaurar o `upgrade` escondido. Esta mudança não possui
rollback de dados porque não altera volumes ou bancos. Para clientes, use a
última versão estável homologada até a promoção explícita da candidata.

## Como explicar para a comunidade

“O Setup MNO deixou de atualizar a VPS inteira durante a instalação. Agora ele
instala somente o que precisa, sem abrir perguntas escondidas. Se o Ubuntu ou o
Debian devolver um erro real, o Setup para e mostra onde encontrar o log, em vez
de fingir que deu certo.”
